# S0 评测合同、基线及组件选型

日期：2026-10-17（北京时间）。数据/门槛版本 s0-fixtures-v1；现有生产代码基线 main 1c78bbe。结论：S0 交付可运行，最终业务质量门槛尚未通过。

## 数据与防止调参污染

50 个虚构来源，120 道独立查询：80 道有依据、40 道无答案/过期/停用/未来/草稿诊断/冲突/跨项目/客户归属/个人邮件/恶意工具参数/检索故障。开发与保留各 60 题，各含 40 有依据与 20 负向；16 题需要跨条目依据。中文/英文及跨语言标签由必要依据语言复核，位置和引用可机器校验。

题目包含主题相关改写，50 来源是小型人工构建 corpus，不宣称 120 题统计独立、行业代表性或覆盖所有攻击。冻结前对必要依据、跨语言、不同权限情形及管理员草稿诊断作标签审查，早期试跑已废弃；未修改生产检索算法。最终冻结版本为验证运行保护与跨平台字节稳定性做了重复运行，核心质量指标一致；所附为最后一次，未据此调整生产检索或组件选型；组件选型只读取 probe-set 的 12 道开发题。后续不得用保留题调参数，若已使用须新增独立保留集并明确版本。

文件锁见 server/evaluation/knowledge/manifest.json。标签记录项目/身份/客户、必要原文及位置、条件、禁止承诺、预期状态。所有公司、客户、政策、证书和价格均为虚构，不可复制为真实业务知识。

## 固定门槛（不降低）

- 保留集必要依据 Recall@10 ≥90%；有充分依据的问题正确回答覆盖 ≥90%。
- 普通事实引用支持 ≥95%；关键承诺依据/条件/位置正确覆盖 100%；评测中无依据的价格/MOQ/交期/运费/认证承诺为 0。
- 缺资料/过期/冲突/故障等负向状态分类 ≥95%；指定强约束案例全部正确或安全阻断。
- 项目/用户/个人邮箱越权、停用/过期/未发布误用为 0；缓存/重排/模型上下文同样适用。
- 五类邮件、人工审核、版本更新、幂等、恢复和故障链路实际通过；不得自动发送真实邮件。
- 机器 profile win11-ultra7-cpu4-s0-v1，1 万个独立片段、并发 2、热模型，包含查询向量化/检索/重排的 P95≤5000ms；冷启动、解析和整封邮件另报。

固定机器：Windows 11 26200，Intel Core Ultra 7 265F（20 逻辑处理器），约 31.65GiB RAM；Node 24.19.0、Python 3.12.14。推理 CPUExecutionProvider，intra=4/inter=1；RTX 5060 Ti 未使用。详细机器/门槛见 [machine.json](knowledge-s0-results/machine.json)。资源不足只能报告和提出调整，未经用户确认不能放宽。

## 当前关键词检索实测

| 集合 | 有依据题 | 必要依据 Recall@10 | MRR@10 | 负向状态分类正确率 |
| --- | ---: | ---: | ---: | ---: |
| 全集 | 80 | 76.88% | 0.3458 | 62.50% |
| 开发 | 40 | 81.25% | 0.3667 | 60.00% |
| 保留 | 40 | 72.50% | 0.3250 | 65.00% |

全集英语有依据题 Recall=84.38%，中文=65.62%；跨语言必要依据 Recall=72.62%。总状态分类正确率=52.50%，定义为 observed==expected 的逐题平均，不是邮件回复准确率。

真实内存数据库服务调用延迟 P50=1.725ms / P95=4.123ms；包括权限查询/证据审核，不含网络 LLM、解析、Embedding 或重排。仅 50 来源、单并发，不能与最终负载门槛混算。

Recall 针对有依据题，按每题找到必要 clause 数/应找到数求平均。命中不只检查来源 ID；还检查原文片段或明确结构化字段及版本。MRR 记录既有返回顺序，基础销售规则占据前面位置，因此即使业务来源排在非基础结果第一位，原始 reciprocal rank 也可能是 1/2。工具实际返回最多 4 条基础规则＋6 条其他资料，不伪造 10 条结果。

负向状态的预测来自既有 bundle/review 的 status 和 issues 映射；没有模型分类器或利用答案标签。大量低相关旧资料的 issues 会干扰该状态映射，此指标用于暴露现有状态表达的不足，不证明 LLM 理解能力。按主题、语言、逐题排名与失败详见 [baseline.json](knowledge-s0-results/baseline.json)。运行报告保留源代码/fixture 哈希、base commit 与 dirtyTree，允许还原提交前运行环境。

## 权限与质量缺口

知识跨项目、外客户、恶意工具额外 projectId 等在这些样本中未返回受限知识；但个人邮件 n29/n30 在“关联客户当前归自己”时仍可被读取，偏离默认私有的目标合同，记为 2 次受限读取。另两个删除/跨项目邮件样本被拒绝。实际没有真实邮件泄漏测试；本轮全部为内存中的虚构记录。

当前读取按客户共享、保存回复按个人邮箱限制；两者不能混为“个人邮箱隔离全通过”。这需要在后续把默认私有/显式共享模型落实到读取和线程聚合，进入任何邮件模型/索引之前完成。

其他缺口：检索相关性/多依据召回不足；低相关过期/冲突条目影响状态；未发布专门诊断不足；条件范围主要靠浅层规则；纯翻译非数字承诺尚无完整语义核对。S0 未接入生产语义检索，也未生成/评价真实客户邮件。缓存、HTTP 认证、完整提示注入、端到端索引生命周期和最终引用/承诺支持率均未在本轮新测。

## 组件实测与选择

同一组 12 道开发题、43 个当前有效非基础知识来源；先按项目过滤再排名/重排。两张 OCR 图片使用相同虚构 MOQ/交期业务文字，分别干净和旋转 2°，不是检索题的识别率。禁止外部 HTTP 推理，Python socket 连接被拒绝，ONNX telemetry 关闭。

| 候选/组件 | 实际运行与结果 | 决定 |
| --- | --- | --- |
| Xenova/all-MiniLM-L6-v2 INT8 | 384维；约23MB权重；12题来源级 MRR=0.7847，Recall@10=100.00% | 英文轻量比较项，不作默认 |
| sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2 AVX2 INT8 | 384维；约118MB权重；12题来源级 MRR=1.0000，Recall@10=100.00%；加载＋43文档＋12查询约1.006s | 初始本地 Embedding |
| cross-encoder/mmarco-mMiniLMv2-L12-H384-v1 AVX2 INT8 | 真实query/document推理；每题最多20候选，重排P95=79.64ms | 初始多语言 Rerank；S3消融后决定使用条件 |
| SQLite 3.53.1＋sqlite-vec v0.1.9＋FTS5 | 真实向量过滤检索、关闭重开、停用排除及英文FTS5烟测；1万行向量查询P95=14.65ms | 初始本地派生索引；精确扫描，不是ANN |
| RapidOCR ONNX Runtime 1.4.4＋自带PP-OCR | 两图归一化CER均为0.85%；73/19均保留；单图约1.349/1.213s | 初始本地OCR |

整个顺序探针采样进程内存峰值约 950.51MiB；它不是逐组件隔离峰值，也不是生产容量证明。向量负载用 43 个真实模型向量复制为 1 万行，不代表一万独立文档；未做并发2与完整检索链路压测。FTS5仅做英文功能烟测，中文分词/稀疏索引质量在S3实现。

小样题的来源级 Recall/MRR 与基线 clause级/含基础规则排名的指标不同，不能用这组满分宣传“系统已经提升到100%”。重排没有在该小样本证明额外排名收益，S3必须保留成本/质量消融。OCR 尚未验证复杂照片、低清证书、多栏/表格和PDF页渲染。Embedding探针128 tokens、重排256 tokens，长表格条件截断风险必须在S1/S3验证。
