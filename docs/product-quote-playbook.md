# 产品目录、报价核对与项目行业卡

日期：2026-10-30
适用版本：V2.6

## 一、产品 / 规格 / 价格目录

入口：侧边栏「产品价格」。

产品目录是**内部报价依据**，不会自动变成客户承诺，也不会替代正式报价单。每个项目独立保存，SKU 在同一项目内唯一；删除操作实际是归档，归档后不再参与报价核对。

### 字段

| 字段 | 说明 |
|---|---|
| `sku` | 必填，字母、数字、点、下划线和连字符，保存时统一转大写 |
| `name` | 必填，产品名称 |
| `category` | 分类，例如 `首饰袋` |
| `specs` | 规格数组，每项含 `code`、`name`、`value`，可选 `unit`、`notes` |
| `priceTiers` | 阶梯价数组，按 `minQuantity` 升序且区间不能重叠 |
| `moq` / `leadTime` | 文本说明，例如 `100 pcs`、`25–30 days` |
| `status` | `active` 或 `archived` |

`priceTiers` 每项：`minQuantity`、可选 `maxQuantity`、`unitPrice`、`currency`（USD/EUR/GBP/CNY），可选 `moq`、`leadTime`、`notes`。`maxQuantity` 留空表示该档无上限；单价必须大于 0。

### 新增 / 编辑

页面表单直接填写 SKU、产品名称、分类、MOQ、交期和说明；规格和阶梯价使用逐行编辑器：

- 规格：填写规格编码、规格名称、规格值，可选单位；同一产品可以添加多条规格。
- 阶梯价：填写起订数量、最高数量、单价和币种；上一档填写最高数量后，下一档从更高数量开始，最后一档最高数量留空表示无上限。
- 不需要规格或价格档时，可以留空；保存时不会再出现 JSON 输入。

### 批量导入 Excel

页面「下载模板」提供 Excel 模板，模板包含三个工作表：

| 工作表 | 内容 |
|---|---|
| 产品 | 一行一个 SKU，填写 SKU、产品名称、分类、状态、MOQ、交期、说明、备注 |
| 规格 | 同一 SKU 可多行，填写规格编码、规格名称、规格值、单位 |
| 阶梯价 | 同一 SKU 可多行，填写起订数量、最高数量、单价、币种、该档 MOQ、该档交期 |

「填写说明」工作表包含字段说明和示例。导入按 `projectId + sku` 覆盖同项目已有产品；单次最多 500 个产品。每个项目使用同一模板单独导入，产品目录不修改历史报价单。模板文件也保存在 `docs/templates/产品价格导入模板.xlsx`。

## 二、报价核对

入口：

- 客户详情 →「报价单」卡片 →「报价核对」：手工输入产品名称/SKU 与数量。
- 邮件中心 → 打开来信分析 →「报价核对」：从分析结果读取客户产品与数量。

核对逻辑是确定性的，不调用模型、不编造价格：

1. 在当前项目启用产品中按 SKU/产品名匹配，必要时做受限模糊匹配（模糊匹配会显示“需人工确认”）。
2. 按数量选择阶梯价；没有数量时显示“缺数量”，数量超出档位时显示“需确认”。
3. 与该客户最近 10 张报价单中对应产品的单价、币种、数量比较。
4. 如果邮件分析中提取到客户提到的价格，低于目录价时标记“低于目录价”。

状态：

| 状态 | 含义 |
|---|---|
| `matched` | 目录价、数量档与历史报价一致 |
| `catalog_missing` | 产品存在，但客户还没有对应正式报价单 |
| `product_missing` | 产品目录没有匹配项，先维护 SKU/规格 |
| `quantity_missing` | 没有明确数量，不能锁价 |
| `price_mismatch` | 币种或价格与目录不一致 |
| `below_catalog` | 历史价/客户目标价低于目录价，禁止直接沿用 |
| `review_required` | 模糊匹配、数量档变化或需要人工确认 |

报价核对不会写回报价单、客户状态或草稿；正式回复仍需业务员生成并审核正式报价。页面中的「产品价格」为空时，先由项目管理员导入产品。

## 三、项目行业卡 / 偏好卡

入口：知识库 →「行业卡」（管理员可见）。

卡片是写作策略，不是事实证据。卡片内容不会进入 RAG 证据包，也不能作为价格、MOQ、交期、认证、产能、质保、免费样品、独家或法律承诺的依据。导入卡片只影响开发信的选卡和写作方向。

内置卡片覆盖：

- Genesis：`I01`–`I40` 行业卡，`P01`–`P08` 偏好卡
- IRONHUE：`IH01`–`IH40`，`IHP01`–`IHP10`
- VELATURO：`VA01`–`VA40`，`VAP01`–`VAP10`

每个项目独立保存。没有导入时使用内置卡片；导入后该项目优先使用导入卡片，导入的偏好卡不会回退到内置偏好卡。

### 导入 JSON

```json
[
  {
    "id": "CUSTOM-I01",
    "kind": "segment",
    "name": "项目专属细分客户",
    "signals": "客户官网或档案中的信号",
    "products": "本项目产品类别",
    "logic": "只写由客户事实支持、且项目已批准的价值逻辑",
    "avoid": "不写未批准的价格、MOQ、认证或交期",
    "cta": "一个低负担的下一步",
    "prepare": "规格表或项目案例",
    "check": "内部注意事项，不进入客户正文",
    "subjects": ["A relevant subject for [Brand]"],
    "keywords": ["keyword-from-customer-site"]
  },
  {
    "id": "CUSTOM-P01",
    "kind": "preference",
    "name": "项目专属采购偏好",
    "signals": "quality / total cost / lead time",
    "products": "",
    "logic": "按客户已表达的标准排序，不猜预算",
    "avoid": "不把偏好写成承诺",
    "cta": "与评估标准对应的下一步",
    "prepare": "可按偏好比较的资料",
    "check": "",
    "subjects": [],
    "keywords": []
  }
]
```

每张卡必须有 `id`、`kind`（`segment` 或 `preference`）、`name`；其余字段可留空。单次最多 200 张，ID 不能重复。页面「载入格式示例」可生成可直接编辑的模板。

导入后下一封新生成的开发信生效；已生成草稿不会被改写。

## 四、边界

- 产品目录、报价单、知识库事实和行业卡是四层不同数据：目录用于内部比价，报价单是客户历史交易，知识库是事实证据，行业卡只是策略。
- 任何价格、MOQ、交期、认证、产能、质保、免费样品、独家或法律条款，发送前仍按现有高风险审核规则由人工确认。
- 报价核对不会自动发送任何邮件。
