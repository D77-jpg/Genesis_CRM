# P2 多租户、Worker、存储与计量验收报告

- 版本：2.6.0
- 日期：2026-11-04
- 分支：`feat/p0-cookie-session`
- 范围：组织租户层、独立后台 Worker、对象存储抽象、错误监控与指标、组织计量与账单

## 1. 完成内容

### 1.1 组织租户层

- 新增 `Organization`、`UsageRecord`、`BillingInvoice` 模型。
- 所有业务模型统一增加 `organizationId`；`Project`、`EmailSuppression` 的全局唯一索引改为组织内唯一。
- `tenant.plugin.ts` 在请求上下文存在时，为 `find/findOne/countDocuments/distinct/update*/delete*/findOneAnd*` 追加组织条件，并为 `aggregate` 前置 `$match`。
- `requireAuth` 通过 AsyncLocalStorage 注入当前组织；平台运营路由使用显式 bypass 上下文。
- 启动时幂等创建默认组织，并把 P2 之前的项目、用户、业务数据回填到默认组织。
- 默认组织使用企业版限额，避免已有自托管数据因 P2 升级被突然限流。
- 平台管理员使用 `User.isPlatformAdmin`，不新增业务角色；普通组织管理员只能管理本组织。

### 1.2 独立后台 Worker

- 新增 `server/src/worker.ts`，提供 `:5100/health`、优雅停机和独立进程入口。
- 后台任务集中到 `server/src/background/runtime.ts`，API 与 Worker 共用同一套任务实现。
- API 进程在 Compose 中设置 `RUN_BACKGROUND_JOBS=false`；Worker 独占邮件队列、收件箱同步、获客、自动开发、跟进、Agent、官网调研和知识库任务。
- Worker 健康检查同时校验 MongoDB 连接状态。
- Compose 增加 Worker 健康检查，并与 API 共享上传/备份卷。

### 1.3 对象存储抽象

- 新增 `storage.service.ts`，支持 `local` 和 `s3` 两种提供方。
- S3 使用 SigV4 签名，支持自定义 endpoint、region、bucket、路径风格（MinIO）。
- 附件记录增加 `storageProvider` 和 `storageKey`；下载/删除按提供方路由。
- 本地存储拒绝路径穿越；存储用量按上传/删除增量计入组织 `storage_bytes`。

### 1.4 错误监控与指标

- 新增 Prometheus 兼容的 `GET /api/metrics`，包含 HTTP 请求计数、匹配路由计数、耗时摘要、进程运行时间和内存。
- 指标标签使用 Express 匹配路由；未匹配请求聚合为 `unmatched`，避免 URL 中的 ID/token 造成高基数。
- 新增有界错误环形缓冲（最多 100 条），5xx 统一捕获并脱敏密码、token、cookie、Authorization。
- 平台管理员可通过 `GET /api/platform/errors` 查看最近错误。

### 1.5 组织计量与账单

- 套餐目录：
  - Starter：$49/月，5 用户、2 项目、5,000 邮件、100 万 AI Token、5GB。
  - Growth：$149/月，20 用户、10 项目、50,000 邮件、1,000 万 AI Token、50GB。
  - Enterprise：$499/月，200 用户、100 项目、500,000 邮件、1 亿 AI Token、500GB。
- 邮件发送前预留额度并计入 `emails`；Agent 结算计入 `ai_tokens`；附件上传计入 `storage_bytes`。
- 超额在发送/上传前失败关闭，返回套餐额度错误。
- 组织管理员可查看当前组织资料、用量、套餐和账单草稿；平台控制台可跨组织查看、暂停/恢复、创建组织和生成账单草稿。
- 账单为估算草稿，实际收款仍由外部财务/支付流程处理。

### 1.6 全站英文界面

- 新增 `AutoTranslate` DOM 桥，覆盖旧页面的静态 UI 文案、按钮、表头、占位符、标题和 `aria-label`。
- 使用本地精确词表和受限短语表，不调用外部翻译网络，不把客户资料发送到第三方。
- 客户名称、邮件正文、知识库正文和用户输入内容保持原文；短语替换不作用于表格正文和用户内容区域。
- 新增组织、套餐、平台控制台页面及导航的双语文案。

## 4. 运维要点

1. 生产 Compose 中 API 设置 `RUN_BACKGROUND_JOBS=false`，Worker 设置 `RUN_BACKGROUND_JOBS=true`。
2. API 与 Worker 必须使用相同的 `JWT_SECRET`、`MAIL_CREDENTIAL_ENCRYPTION_KEY`、MongoDB URI 和存储配置。
3. 多副本 API 建议使用 `STORAGE_PROVIDER=s3`；本地存储仅适合单机或共享卷。
4. `GET /api/metrics` 默认公开，生产建议在 Nginx/反向代理限制来源。
5. 默认组织只用于旧数据承接；新客户组织应从平台控制台创建，并使用独立管理员账号。
6. 暂停组织后，该组织非平台管理员的请求会被拒绝；恢复后立即恢复访问。
7. 账单草稿不自动扣款，不同步到支付网关；如接入 Stripe，应新增外部客户/订阅 ID 映射。

## 5. 已知边界

- 组织级 AI 服务配置在 HTTP 请求内按组织隔离；后台 Worker 没有组织上下文时使用环境变量默认 AI 配置，避免误用其他组织的密钥。
- 附件存储的 S3 路径风格和签名已实现，但当前自动化测试使用本地提供方；上线前应在目标 S3/MinIO 做一次真实上传/下载/删除验收。
- 旧页面英文覆盖依赖本地词表，新增中文 UI 时应同步补充 `web/src/i18n/auto-translations.ts`，或直接使用 `t()`。
- `estimatedDocumentCount` 不参与租户过滤，已从租户插件中移除；业务代码不应使用它统计租户数据。
