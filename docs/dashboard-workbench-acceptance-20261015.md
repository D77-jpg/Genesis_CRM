# CRM 仪表盘工作台优化验收 · 2026-10-15

## 结果

仪表盘从多组同级卡片改成有主次的销售工作台：

- 原 13 个独立数字卡片收敛为一条业务概览；总客户、待开发、近 7 天发送、开发率直接展示。
- 客户清单成为页面主体；待跟进、最近客户、跟进动态、邮件记录共用同一个区域。存在到期或逾期任务时默认打开待跟进，否则展示最近客户。
- 桌面右侧紧凑显示逾期、未来跟进、草稿、失败邮件和缺少邮箱提醒，今日进度用简短数字展示。
- 销售阶段、行业、客户等级和发送趋势放进可展开的业务分析；原有汇总信息仍可查看。
- 移动端采用紧凑概览和单列清单，客户加入/跟进时间保留在客户名称下方。所有颜色沿用现有语义变量，支持深色模式。

## 数据与动作

继续使用原有 GET /api/stats/overview，不更改数据库、权限、客户归属或邮件发送逻辑。清单和提示没有静态业务数据。概览与提醒跳转前先清除上次的列表搜索、状态等条件，再设置明确的目标筛选。

行业与等级占比按当前全部可见客户计算，避免仅取前几项后把占比错误放大。

## 验收

- 前端生产构建（含 TypeScript 检查）通过。
- 原有前端回归：guarded braces 20 项、客户清空字段 2 项、Agent 内容与安全渲染 3 项，合计 25/25。
- 已登录本地页面：概览与清单展示当前用户实际可见数据；无到期任务时默认最近客户。
- 实测今日跟进、待开发、未来跟进、无邮箱、草稿和失败邮件入口，目标筛选正确。
- 实测先搜索特定客户，再从概览打开全部客户，旧搜索和跟进条件已清除。
- 实测键盘方向键切换页签、跟进与邮件空态，以及展开业务分析；刷新按钮正常。
- 桌面 1440×1000、手机 390×844 和浏览器默认尺寸均检查；手机页面宽度没有超过可视宽度，四个页签点击高度均为 44px。
- 深浅色检查完成，已恢复用户原先的浅色模式和浏览器默认尺寸。

本次没有为了展示效果新增客户、跟进或邮件测试数据，也没有发送邮件。
