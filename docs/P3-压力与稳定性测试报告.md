# P3 压力与稳定性测试报告

测试日期：2026-11-04  
对象：本仓库 `feat/p0-cookie-session` 工作树（P3 迁移、API 与公共页已完成）  
脚本：`server/scripts/load-test.ts`  
原始数据：`docs/P3-load-soak-5m.json`、`docs/P3-load-soak-30m.json`

## 1. 测试环境

| 项 | 值 |

| 日期 | 2026-11-04 |

## 2. 结果

### 2.1 短时压力（30 秒，20 并发）

- 总请求：13,125
- 吞吐：468.28 req/s
- 错误率：0%
- p50 / p95 / p99：24.9 / 103.9 / 124.1 ms
- 最大延迟：160.1 ms
- 进程 RSS：175.2 → 390.2 MiB；heapUsed：95.2 → 147.0 MiB（短时分配器增长，非稳态判断）

### 2.2 5 分钟稳定性（15 并发）

- 总请求：150,939
- 吞吐：508.17 req/s
- 错误率：0%（全部 HTTP 200）
- p50 / p95 / p99：17.5 / 71.5 / 86.6 ms
- 最大延迟：127.1 ms
- 进程 RSS：339.1 → 339.0 MiB（基本持平）
- heapUsed：107.7 → 140.4 MiB（仍在垃圾回收正常波动区间，无持续线性增长证据）
- 结果：**通过**（p95 预算 1,500 ms，错误率预算 1%）

### 2.3 30 分钟稳定性（15 并发，跨 access token 过期）

- 总请求：1,027,888
- 吞吐：571.04 req/s
- 错误率：0%（全部 HTTP 200）
- p50 / p95 / p99：15.4 / 65.9 / 80.8 ms
- 最大延迟：429.9 ms
- 进程 RSS：151.8 → 356.1 MiB（进程冷启动后 30 分钟；无持续线性增长，后段稳定在约 390 MiB）
- heapUsed：77.1 → 133.4 MiB（GC 后回落，无 OOM）
- 测试跨过默认 15 分钟 access token 过期点；压测脚本通过 `/auth/refresh` 轮换会话，所有请求仍为 200。
- 结果：**通过**（p95 预算 1,500 ms，错误率预算 1%）

## 3. 限流验证

初次用默认 `API_RATE_LIMIT_MAX=600/分钟` 跑 20 秒时，出现 47,923 个 HTTP 429、错误率 65.85%，p95 5.6 ms。说明限流器按预期保护 API，而不是容量不足。压测必须在隔离环境临时提高上限；生产保持 600/分钟，或按客户套餐/网关层调整。

## 4. 观察与限制

- 本测试只覆盖**只读**接口，不代表发送邮件、导入、AI、附件上传/下载或报价写入的容量。
- 单机本地 MongoDB + 单 Node 进程，不能外推生产多副本、网络、TLS、反向代理和真实 MongoDB 规格。
- 30 分钟仍属于**稳定性冒烟**，不是 24–72 小时长时间稳定性测试；不能据此声称 24×7 无泄漏。
- `/health` 返回的进程内存是 Node 进程自身，不含 MongoDB、反向代理和外部服务。
- 测试数据与生产数据混用本地开发库；生产/staging 压测必须使用独立数据库和合成/脱敏数据。

## 5. 正式上线前的长稳计划

在 staging 执行至少 **24 小时**（推荐 72 小时）持续只读 + 周期性写入混合负载：

```powershell
$env:LOAD_BASE_URL='https://staging-crm.example.com/api'
$env:LOAD_USERNAME='load-test'
$env:LOAD_PASSWORD='<staging-only>'
$env:LOAD_DURATION_SECONDS='86400'
$env:LOAD_CONCURRENCY='20'
$env:LOAD_P95_BUDGET_MS='1000'
$env:LOAD_REPORT_PATH='..\docs\P3-load-soak-24h.json'
npm run load --prefix server
```

验收标准：

- 错误率 < 0.1%，无非预期 5xx；
- p95 < 1s，p99 < 2s（以 staging 规格为准）；
- RSS 在预热后无持续线性增长（每 6 小时采样，末段与首段相差 < 20%，且无 OOM）；
- 期间完成一次滚动重启、一次备份恢复演练、一次邮件队列积压恢复；
- 与 APM/Mongo 慢查询、连接池、事件循环延迟一起分析，不能只看客户端延迟。

## 6. 结论

当前构建在本地只读冒烟负载下表现稳定：30 分钟、约 103 万请求、0 错误，限流与错误处理正常，未发现崩溃、OOM 或错误率异常。**不能**据此替代生产容量规划、全链路写入压测或 24–72 小时长稳；这些仍是公开上市前的待办门禁。
