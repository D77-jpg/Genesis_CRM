## 2. 数据模型

V2.5 未新增无限增长的事件集合，而是扩展现有 `DevelopmentLetter`：

- `deliveryContent`：实际发给 SMTP 的追踪版 HTML，`select: false`，CRM API 不返回。
- `tracking.prepared / enabled`：区分「已准备」和「成功投递后已激活」。
- `tracking.openTokenHash`：开信 token 的 SHA-256 摘要。
- `openedAt / openCount / lastOpenedAt`：首次、累计和最近打开。
- `clickedAt / clickCount / lastClickedAt`：整封邮件的首次、累计和最近点击。
- `tracking.links[]`：最多 100 个可追踪外部链接，每个保存 token hash、原始 URL、首次/最近时间和计数。

索引：

- `tracking.openTokenHash_1`：unique + sparse。
- `tracking.links.tokenHash_1`：unique + sparse 多键索引。
- 继续使用 V2.1 `requestKey_1` unique + sparse 保证任务幂等。

计数通过 MongoDB `$inc/$min/$max` 单文档原子更新，重复打开/点击不会持续增加文档或 Timeline 记录。

## 3. Tracking API

### `GET /api/tracking/o/:token.gif`

- 不要求 JWT。
- token 合法且追踪已激活时，更新打开时间/计数，并将 `sent` 更新为 `opened`。
- 总是返回小于 100 bytes 的 1×1 透明 GIF；无效 token 也不暴露邮件是否存在。
- 设置 `no-store/no-cache`，不返回任何 CRM 数据。

### `GET /api/tracking/c/:token`

- 不要求 JWT。
- 只用 token hash 查找发送时已保存的 URL，不接收 `url`/`redirect` 查询参数。
- 点击计数成功后返回 `302`，并设置 `Referrer-Policy: no-referrer`。
- 无效 token 或非法目标 URL 返回 404，不做跳转。

## 4. Open / Click 流程

1. 邮件渲染并经现有 HTML 清洗。
2. 任务首次持久化时，对 HTML 发送副本加入每件/每个收件人/每个任务唯一的 Pixel，并为每个可追踪外部链接生成独立 token。
3. 队列重试读取同一 `deliveryContent`，不重新生成 token。
4. SMTP/Mock 明确接受后才将 `tracking.enabled` 置为 `true`；失败、待核实或取消任务不会记录行为。
5. Pixel 命中时单文档原子累计 Open；Click 命中时原子累计邮件和具体链接。
6. 首次 Open/Click 从 `openedAt/clickedAt` 派生到 Timeline，每封邮件每类仅一条；后续次数在邮件摘要中展示。

## 5. 隐私与安全

- token 使用 32 bytes（256-bit）密码安全随机数，以 base64url 放入 URL。
- 数据库只保存 token SHA-256 摘要；URL 不包含 customerId、email、JWT、messageId 或其他 CRM 标识。
- Tracking token 从 HTTP access log 中排除。
- 不保存 IP 或 User-Agent，遵循数据最小化。
- Click Endpoint 不允许请求方提供跳转地址，生成和跳转前都校验 URL；只允许有 hostname、无 userinfo 的 `http/https`。
- `javascript:`、`data:`、`mailto:`、相对地址均不追踪。
- URL/文案含 unsubscribe/opt-out/退订、`rel=unsubscribe`、`data-no-track`的链接不追踪。
- Tracking 域名、CORS 中的 CRM 域名及 localhost 内部链接不追踪。
- 公开端点复用全局限流；计数为固定大小原子更新，无复杂联表或事件插入。
- 页面显示「邮件客户端、图片代理或隐私保护可能影响统计，数据仅作互动参考」，不宣称为 100% 真人打开。

## 6. 权限验收

- Pixel/Click 端点在不携带 JWT 时正常记录/跳转。
- 公开端点只能对随机 token 命中的已投递邮件计数，不返回客户、邮件正文或行为数据。
- 内部 `GET /api/letters/:id`、`GET /api/mail/:id?direction=outbound` 继续使用 JWT + customer ownership 范围。
- 他人客户的邮件详情和追踪摘要均返回 404；管理员可查看全部。
- 测试中已验证 sales/other/admin 三种访问路径，无存在性泄露。

## 9. 已知问题与部署注意事项

1. Open Tracking 天然会受 Gmail/Outlook/Apple Mail 等图片代理、预加载、缓存和隐私保护影响，不能认定为「客户本人 100% 真实打开」。
2. 生产环境必须将 `TRACKING_BASE_URL` 配置为收件人可公网访问的 HTTPS 地址；默认 localhost 仅用于本地开发。
3. 单封邮件最多改写 100 个合法外部链接，超出部分保持原链接且不追踪，用于限制单文档大小和索引成本。
4. lint 仍有 6 条既有 warning（Fast Refresh 文件导出和一条既有 Hook dependency 提示），均不在 V2.5 修改文件的新逻辑中，不影响构建或功能。
