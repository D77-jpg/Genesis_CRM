- 错误密钥在数据库写入前拒绝；非空目标和源库覆盖拒绝；有活动任务/未确认停写/源指纹变化拒绝；新目录和文件规模受限。曾因夹具自动建表未完成触发source_changed，保留失败事实，等待初始化后通过。它是演练库工具，不能直接覆盖真实库。

## 仍存在的限制与S8入口

1. S4/S5真实模型事实、承诺、问题覆盖和五类邮件文案未达最终验收；不能以本地回归/模拟调用替代。S8先补齐授权网关的开发/首次保留测量，不额外外传资料。
2. 多主机共享Mongo指针但各持独立SQLite没有支持；单机索引已通过，异机缺失安全失败。更大规模、混合建索引与业务峰值、多租户公平性、重压长时间 soak 未验收。
3. Python环境/网络审计与Job资源限制不等于完整原生OS沙箱。独立低权限身份/容器文件系统隔离尚未落实，不能宣称抵御原生解析库漏洞。
4. 实际恢复是停写隔离库，不是运行中数据库点时快照；通用mongodump/mongorestore本机未安装，现有工具7项模拟测试不冒充生产恢复。真实介质、密钥托管、保留期、目标主机恢复仍在上线待办。
5. 监控按项目近7天聚合，检索计数90天TTL；生产autoIndex关闭时要在部署预检中单独建立唯一/TTL索引，不能假定已安装。进程内熔断/资源状态不是跨主机分布式监控。
6. 同步日志已限量和文件轮换；控制台宿主仍需保留限制。LLM累计tokens/配置估价不是实际账单，失败usage未知。端到端模型生成仍需下一阶段授权质量测量。
7. 本次不部署生产、不配置域名/TLS、不迁移真实客户、不自动发布真实知识。S8必须在全部PR合入、干净SHA下完整页面验收，业务资料审核与工程验收分开。
