# 知识库改版：两个页签、一个文件一篇资料（2026-10-21）

这次不是加功能，是把知识库的“机器流水线”从人面前拿开。

## 改之前为什么看不懂

真实项目里的《01-客户画像.md》只有 8,588 字节，解析器按空行切段，**切成了 88 段**，平均每段 88 个字。页面把这 88 段当成 88 个待办：

1. 每段显示“内容 1 / 内容 2 / 内容 3”和 `文字区间 0–16（Unicode 字符）`，要逐段点“加入待审核资料”；
2. 再到“资料审核与维护”逐条填标题、分类、适用条件、来源、有效期；
3. 再到“检索维护”点“更新检索资料”，等状态变成“资料已就绪”；
4. 助手才能用到这份文件。

中间还夹着 `第 1 次解析`、`代次`、`配置校验`、`有效发布资料`、`片段` 这些只有程序需要的词；“检索维护”整页（模型维度、代次、回滚、清理）是运维界面，却放在业务菜单里。真实库里还混着 5 条 `Fixture / Fictional` 验收数据，列表更像一堆碎片。

## 现在的用法

管理员（知识库 → 资料管理）：

1. 点“上传文件”。支持 TXT / Markdown / PDF / Word / Excel / CSV / 图片。
2. 文件读完后自动弹出**整篇**预览：标题、分类、来源已经填好，往下就是全文。
3. 确认没有不该给客户看的内容，点“收录，助手可用”；不确定就点“只存草稿”。

业务员（知识库 → 资料库）：按分类或关键词找已发布的资料，阅读，选客户准备开发信。和以前一样。

不再需要的动作：逐段“加入待审核资料”、逐条填表单、手动“更新检索资料”。

## 页面的四个状态

- **待确认**：草稿，助手还没用上。可以看全文、编辑、发布、删除。
- **已发布**：助手正在使用。可以看全文、编辑（产生新版本）、停用、删除。
- **已停用**：折叠在“已发布”下面。停用只是让助手不用，条目还在；要彻底清掉，点它后面的“删除”。
- **原始文件**：上传过的文件、解析状态、是否已收录。失败可重新读取，已收录可回看原文，也可以删除。
- **助手检索**（顶部一格）：`已就绪 · N 篇` / `正在更新…` / `需要更新` / `暂无资料`。发布、修订、停用后会自动重建检索；失败时“技术信息”里有手动重建。

## 「有提示」是什么意思（2026-10-21 补）

解析器对每份文件会给若干条系统提示；之前只要有任何提示，就把整份文件标成“部分内容需核对”，界面还写成“有部分内容没有读到”——这个说法是错的，实际并没有丢字。

提示分两类：

- **内部限制**：`上下文超过 128 tokens；整段保留…`。这是旧的片段审核流程留下的分块上限，现在整篇收录由检索侧自行分段，和用户无关，界面不再显示。
- **需要人看一眼的**：表格表头/合并单元格/公式、扫描件 OCR、某页没识别到文字、正文里出现“忽略指令”一类文字。这些翻译成白话说清楚，收在文件行的“查看 N 条提示”和收录弹窗的“收录前留意”里；只有 OCR、缺页、指令注入这类才标琥珀色。

接口侧 `GET /knowledge-documents` 现在把片段级提示合并进 `parsing.warnings` 返回，`GET /:id/collection` 也返回 `notes`，界面不再靠猜。

## 删除与重来

- 删除文件：文件、解析记录、片段，以及**从这份文件收录的资料**一起删掉；同一份原文被别的文件复用时，原文副本保留。
- 删除资料：所有版本一起删掉，助手立即停止使用。
- 停用 ≠ 删除：停用后条目还在“已停用”里，助手不用它；删除才是彻底清掉。
- 删除都会二次确认，不可恢复。

## 技术变化

- 新增 `GET /api/knowledge-documents/:id/collection`（整篇预览）和 `POST`（收录）。一个文件生成一篇资料；超过 11,000 字的文件按整块拆成“第 N 部分”，不截断。
- 合并时丢弃 Markdown 的 `---` 分隔线和空段；每篇保留全部 `sourceRefs`（原文件、解析版本、片段位置与哈希），用于追溯，但不再出现在审核界面。
- `importKey = document-collection:<文档>:<解析版本>:<序号>`，重复点击不会产生重复条目。
- 发布复用 `appendKnowledge`，随后 `knowledgeIndexChanged` 自动触发检索重建；不再需要人工点“更新检索资料”。
- 新增分类 `reference`（参考资料），收录时默认使用。它参与检索和事实核验，但不承载价格/交期等承诺；承诺仍应建成 `trade` 并填条件。
- 删除 `knowledge-documents.tsx`（逐段审核）与 `knowledge-index.tsx`（检索维护页）；`view=documents`、`view=index` 旧链接仍会落到资料管理，`document=` 参数会打开原文预览。
- 旧的片段级接口 `POST /knowledge-documents/chunks/:id/draft` 保留，供既有测试和溯源使用，界面不再暴露。
- 编辑表单从 `project-knowledge-manager.tsx` 抽成 `knowledge-entry-form.tsx`，资料管理页与客户页共用。
- 新增 `DELETE /api/knowledge-documents/:id` 与 `DELETE /api/agent/knowledge/:id`；前者连带删除 `sourceRefs.documentId` 指向该文件的资料。
- CSV/XLSX 不再拼成 `a | b | c` 的段落：收录时按行重排成「`### 行标题` + 字段列表」，用表头作字段名；去掉 `[格式: 0]` 解析标记、重复表头和重复的页签名，保留未计算公式的原文。每个记录自带标题，所以跨篇切分不会把一条记录劈成两半（切分仍按 11,000 字，且不超过 12,000 字上限）。
- Markdown 表格原先被解析器按行拆成“每行一张表”，每张表还重复一遍表头后的脚注；收录时按 `table.headerText` 把连续行合回一张表，脚注只保留一份。02-产品资料 因此从 3 篇变成 2 篇，第一张表 10 行只出现一次表头。
- 表格样式改为 `width: max-content` + 单元格 `min-width: 7rem / max-width: 26rem`，表头不换行；窄栏里横向滚动，不再把“中文”挤成“中 文”。
- Word 表格同样是每行一段、表头重复；按 `table.headers/rows` 合并成一张表，单元格里的 `|` 和换行会转义。标题规则也修了：Word 表格第一列是 `#`，旧逻辑把整行当成 Markdown 标题；现在标题行不允许含 `|`，并跳过 `CSV`/`Sheet1` 这类解析器标签，回退到文件名。

## 2026-10-21 资料库阅读页的留白与滚动

- 左侧列表原来用 `0.8fr` 且铺 `bg-muted/15`，只有两三篇时是一整块灰色空板。现在列表固定 `17–20rem`，去掉灰底。
- 滚动不再“一半 sticky、一半翻页”：宽屏下资料库改成**固定高度的双栏工作区**——卡片高度 `calc(100dvh-7rem)`，顶部搜索/分类固定，左栏列表和右栏正文各自在栏内滚动，页面本身不再滚。这样滚轮在哪一栏就滚哪一栏，不会出现“列表跟着页面跑、正文又单独跑”的错位。窗口宽度小于 1280px 时仍是原来的单页滚动。

## 2026-10-21 资料库搜索与正文高亮

- 搜索是全文匹配：标题、正文、适用产品、交易条件都查；空格分隔多个词时要求全部出现；分类与搜索叠加。
- 列表行显示命中片段并高亮关键词，标题命中优先排序；计数写成“找到 N 份含「词」的资料”。
- 正文用 CSS Custom Highlight API（`::highlight(kb-hit)` / `kb-hit-active`）标出所有命中，不改动 React 渲染出的 DOM；命中工具栏放在正文滚动区**上方**（不在滚动容器里，所以不会盖住文字），显示“第 n / N 处”，可上一处 / 下一处跳转，切换资料会自动跳到第一处。浏览器不支持 Highlight API 时只计数、不染色。
- 已知限制：按子串匹配，不做同义词或模糊；被 Markdown 加粗/链接拆成多个文本节点的词可能数不到（例如“绒**布袋**”）。

## 2026-10-21 “本次资料超过处理上限”

- VELLURE 的首封开发信在 `analyze_customer` 阶段失败（`PAYLOAD_TOO_LARGE`）。原因不是客户资料，而是知识库：整篇收录后单条资料 8–11k 字，检索把整篇正文 + 每个片段的排行诊断（`index.chunks` 里重复的 `sourceRefs`，单条能到 1.5MB）一起塞进分析输入，超过 `AI_MAX_INPUT_CHARS=60000`。
