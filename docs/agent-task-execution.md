# 单客户首封开发信任务（P0 / P1）

业务员可在客户详情对话中说“帮我给这个客户写第一封开发信，不要发送”，或在项目对话中指定客户/公司名称。

系统按“定位客户 → 分析与起草 → 保存草稿 → 核对结果”执行。模型只获只读检索工具；明确委托触发的固定工作流可保存草稿，任务执行器没有发信步骤。重名需选择，缺邮箱需补齐；未知 MOQ、交期等不会被当成已知事实。

任务页显示实际检查点和过程记录，可暂停、继续、取消及有限重试；重新打开面板从服务器取回最近 30 项任务。草稿准备完成后自动打开审核页，后续也可手动打开。业务员审核并点击发送；只有真实 SMTP 接受后才完成任务并新增“首封开发信已发送”跟进，模拟、失败、取消和保存草稿均不算真实发送。SMTP 接受不等于客户已收件或已阅读。

## 恢复与权限

- AgentTask 与业务草稿存 MongoDB。后台按租约领取，心跳续约；异常进程租约最多 90 秒后可恢复。
- 分析/草稿分别使用任务级幂等键。写入成功但进度未保存时，恢复读取原记录，不覆盖业务员后续编辑。
- 暂停/取消会阻止继续推进；已经在执行的模型请求可结束，已保存的结果保留。
- 每次推进重验用户启用状态、项目权限、角色与客户归属。后台角色只会收窄，不随账号升级扩大。
- 通用对话最近 60 条、消息列表最近 200 条，避免长会话漏掉最新指令。模型超时、输出不合规、额度、权限变化分别反馈。
- 应用启动即运行草稿任务轮询（测试进程关闭）。不要求启用收件同步/邮件后台任务；实际发信继续遵守既有投递流程。

## 验证

Agent 测试覆盖重名与归属隔离、失去检查点后的恢复、并发领取、暂停、取消、超时重试、缺邮箱、账号停用，以及再次存草稿不发送。邮件测试覆盖失败/模拟不记跟进、真实 SMTP 接受后仅记一次并完成任务。测试使用隔离数据库及替代投递函数。

本轮限定单客户首封开发信；批量任务、收信事件自动触发、定时持续监控、跨任务长期记忆及通用多工具自主规划不在本轮交付范围。
