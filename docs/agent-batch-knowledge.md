# P2 批量与产品知识

客户列表勾选最多 20 家后点击“Agent 批量准备草稿”，或在 Agent 对话说“给 5 家高优先级客户分别准备首封开发信”。在“批量”页先核对真实名单、要求和预算，再确认执行。

每家客户是独立持久任务：分析、来源摘要、草稿与错误分别保留。批次暂停/取消阻止后续步骤，已生成草稿保留。一家失败不停止其他任务；只重试失败的那一家。自动筛选排除缺邮箱及停止营销客户；手工选中的停止营销客户也会在执行前被阻断。

批次默认每客户 20,000 tokens 上限，合计最高 400,000；每次模型调用前按输入估算与最大输出持久占用额度，失败不退回，防止无限重试。页面“已占用上限”是保守预算，实际 token 使用仍在运行记录统计。全局每日配额继续生效。

“产品知识”页由管理员填入标题、适用产品标签、已核实事实和批准依据，明确点击发布后才供 Agent 使用。新版本保留原文、作者、时间；保存草稿不替换已发布版本，归档后停止新任务引用。内容以 sourceId 与版本关联到分析结果。客户资料/附件属于客户陈述，不能自动转成我方承诺。

当前客户的附件可直接“读取正文”，分析也会读取最新三份附件的受限正文。支持 5MB 内 TXT、DOCX、文字 PDF（前 30 页，正文上限 24,000 字符）；扫描 PDF、图片、受密码保护、损坏、过大或超时的文件明确显示不可提取，不虚构内容。解析在无应用密钥的独立隐藏子进程内执行，有 12 秒与内存上限。缓存每次重新检查客户权限与文件 hash。DOCX 先检查 ZIP 展开上限，不加载外部文件。

业务技能 `first_outreach@2` 固定声明流程、禁止承诺和交付条件；跨步骤摘要来自实际生成并验证的事实，保存在任务中。批量不自动跳转页面，业务员逐份打开原草稿审核发送。

验证：53 项 Agent 测试、94 项邮件测试与前后端类型检查/前端构建通过；包括五客户中一家失败、单独重试后仍仅五份草稿、不同客户不同正文、预算提前阻止、退订阻断、产品版本、实际 PDF/DOCX 正文和缓存越权拒绝。新增解析依赖的审计已通过仓库门禁；沿用已有 SheetJS 临时例外，未新增例外。
