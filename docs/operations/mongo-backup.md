# Genesis MongoDB backup and restore rehearsal (H-12)

This is **Genesis only**; PostgreSQL/Alembic/CRM mapping verification belongs in the separate AutoForceAI orchestration. Nothing here invokes a production restore. Install MongoDB Database Tools (`mongodump`, `mongorestore`), `mongosh`, and Node.js >= 20.19. The script does not load `server/.env` automatically. Provide an explicit database-specific URI from a protected secret store; never commit credentials, key material, archives, or reports. Pass a URI **without** a database path, or with the exact source/target database path. For rehearsals use an isolated MongoDB instance and URI credentials restricted to that instance; the script itself does not prove the server is isolated.

```sh
# Create the directory yourself first, on an access-controlled backup volume.
node scripts/mongo-backup.cjs backup --dir /srv/genesis-backups --db cdlm --uri "$MONGO_BACKUP_URI" --keep-days 30 --keep-count 30 --report /srv/genesis-backups/last-backup-report.json
node scripts/mongo-backup.cjs rehearse --manifest /srv/genesis-backups/genesis-mongo-cdlm-YYYYMMDDTHHMMSSZ-RANDOM.json --uri "$MONGO_REHEARSAL_URI" --target cdlm_restore_test --report /srv/genesis-backups/last-rehearsal-report.json
```

On Windows, use absolute Windows paths and PowerShell environment variables (`$env:MONGO_BACKUP_URI`). Do not put a URI containing secrets into shell history or CI logs; prefer protected environment injection. The URI may be visible in local process listings while MongoDB tools execute; use isolated service credentials and host protections. The script invokes executables without a shell, redacts tool stderr, never prints URI/key, and fails closed on errors.

The backup uses `mongodump --archive=<file> --gzip --db=<db>`; checks nonempty and complete gzip stream; queries `mongosh` for source collection document counts; publishes the archive and manifest via same-directory renames. A manifest includes UTC creation timestamp, database, byte size, SHA-256 of the **stored** archive, encryption flag, collection counts, and random collision-resistant name. The manifest is published last; orphaned archives from interrupted runs are not auto-pruned. Hash/size are rechecked before restore and during retention. Backups are not a transactional point-in-time snapshot on a busy standalone MongoDB: quiesce writes or configure MongoDB-consistent snapshot/oplog policies where needed. Recorded RPO is age since dump start, **not a guaranteed data-loss bound**; establish a real RPO externally and monitor write quiescence/oplog policy. Back up uploads and external secrets separately.

Optional encryption: append `--key-file /outside/repository/mongo-key.hex` to **both** commands. The key file must contain exactly 64 hexadecimal digits (32 bytes); provision it securely with restricted permissions from a secret manager. Encryption is AES-256-GCM with random 12-byte nonce and 16-byte authentication tag. The manifest hashes the encrypted bytes. A compromised key defeats at-rest encryption; store and rotate the key separately from backups. Decrypted temporary plaintext is removed after rehearsal; use encrypted local temporary storage and restrict OS temp access if necessary.

Retention defaults to 30 days and 30 copies; both must be positive integers. Only recognized, validated archive+manifest pairs in a canonical absolute, existing non-root backup directory are unlinked individually. No recursive deletion, symlink traversal, root directory, or unresolved directory is allowed. Malformed backup manifests block retention rather than causing unsafe deletion. An already-published backup remains valid if retention fails; the report then records failure so an operator can investigate. Do not put report JSON under a directory with sensitive customer-access permissions wider than the archive.

Restore is **rehearsal only**: target must have `rehearsal` or `restore_test` in its database name, must differ from the manifest source, and must have no populated collections; no `--drop` is used. The operator must provide a URI for a separate test server and an empty target; do not use a production server account with write access. After restore, source collection counts (including the `projects` Genesis project count) must match; a mismatch returns nonzero and a JSON failure. The script does not delete partially restored test databases: investigate manually in the isolated instance. JSON stdout and optional atomic `--report` file contain `ok`, `failure`, `rtoSeconds`, and `rpoSeconds` (null where not applicable). Rehearsal RTO measures restore plus verification from script start; use alerts and independent scheduling to enforce objectives. Cross-system PostgreSQL rows, Alembic version, CRM mapping and combined RTO/RPO require the companion AutoForceAI H-12 implementation and are **not** validated by this tool.

Run fake-tool safety tests without a database: `node --test scripts/mongo-backup.test.cjs`.
