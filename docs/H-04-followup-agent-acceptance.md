# H-04 跟进建议引擎验收记录

基线：`origin/main` 的 H-03 合并提交 `14e646f`（包含 `4d2dcfb`）。验收范围限定 Genesis_CRM 现有客户分析与邮件分析跟进建议，不新增第二套引擎，不自动发送邮件。

## 验收结论

- 客户分析读取客户档案、Timeline、邮件、既有跟进和报价；模型生成的事实/建议只接受目录内的来源 ID。跟进计划的理由和来源取自**已验证的建议**，人工修改后的计划标注为人工编辑，原始证据不能被理解成对编辑后内容的重新背书。邮件分析展示已验证邮件 ID、理由及原邮件摘录；受保护信号使用安全证据。
- 两种建议均返回跟进方式、目的、时间、理由及来源。过期的模型建议时间不再被静默替换或抹掉，要求重新分析；用户可以编辑未来时间，确认前不写入客户的跟进日期。
- 客户分析经确认更新 `nextFollowUpAt` 并写入 `followup_scheduled` Timeline，重复确认幂等；邮件分析经确认记录一次 FollowUp，若有未来时间同步客户主档，重复确认不新增记录。
- 退订、退信、拒绝和垃圾邮件信号不仅检查当前邮件，还在安排未来营销跟进时检查同客户其他邮件；即使建议生成后新增受保护邮件，确认时仍拒绝。受保护邮件的结果记录不安排后续营销，并清除既有的客户跟进日程（Timeline 记录时间变化）。
- 旧邮件状态建议不能把当前 `won`/`lost` 客户降为其他状态。跨项目、非负责人、负责人转移后的客户分析确认返回 404。
- 业务动作必须调用单独的确认接口；前端展示明确核对勾选，写操作保留审批审计。邮件草稿仍仅保存为 `draft`，不直接发送。

## 自动化证据

`server/tests/agent.test.ts` 包含未授权、编辑和审批、Timeline、幂等、终态防降级、异线程退订、既有日程清理、过期时间拒绝及来源追溯验收。以仓库当前本地分支执行：`npm run test:agent`（32/32）、`npm run test:mail`（79/79）、`npm run test:scratchpad`（3/3）、`npm run test:integration`（23/23）、server/web `npm run typecheck` 与 `npm run build`，均通过。测试使用内存 MongoDB 和 Mock Agent，不调用真实邮箱或模型凭据。

## 边界与后续

邮件正文启发式安全识别可能出现误报，人工须审阅原邮件。MongoDB 客户更新、跟进记录与审计/Timestamp 不是单个事务；极端并发情况下客户状态或邮件信号在最终检查之后变化，现有服务仍有时序窗口，不声明强事务保证。全量历史营销日程的批量清理不在此次按单条审批的范围内。AutoForceAI 阶段 4 状态应在本分支 PR 合并且主线测试通过后，另起独立文档 PR 将 4.1 / 4.4 标记为“验收完成”，避免文档先于代码发布。
