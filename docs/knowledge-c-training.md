# C：审核与自动训练（安全闭环）

本阶段只使用虚构资料、虚构客户和本地审核记录。目标不是用少量样本直接微调模型，而是先把**人工审核 → 可训练样本 → 可解释校准 → 可回退**的闭环做成生产可用；没有足够真实样本前，不自动更新模型权重。

## 交付

| 能力 | 实现 |
|---|---|
| 审核样本自动沉淀 | 业务员每次通过/不通过草稿，自动保存 AI 原稿、人工最终稿、修改比例、审核结论、采用的已发布来源和问题标签 |
| 管理员审核概况 | 新增“知识库 → 质量与训练”页：样本量、通过/不通过、真实修改率、可校准样本、最近样本、反复采用的来源 |
| 自动训练 | 通过稿产生“相似请求 → 人工认可来源”的词项先验；管理员启用后，检索对**已接受**候选做最多 2% 的排序校准 |
| 安全开关 | 默认关闭；管理员可随时暂停。关闭时样本仍收集，但不影响任何检索 |
| 撤销/删除 | 撤销审核会把样本标记为 retracted；删除草稿、客户或批量删除时同步清理训练样本 |
| 权限 | 样本、概况和开关仅管理员可见；只使用本项目数据，不退化为跨项目学习 |

## 审核采集

`DevelopmentLetter` 新增 `aiSnapshot`，只在首次生成带知识依据的草稿时写入：

```text
{ subject, contentText, at }
```

之后人工编辑、保存、审核都不会覆盖这份基线。审核通过或拒绝后，`knowledge-training` 服务写入 `KnowledgeFeedback`：

- `aiSubject/aiBody`：AI 原稿；
- `finalSubject/finalBody`：审核后的最终稿（不通过时使用当前草稿内容）；
- `editRatio`：字符级修改比例，仅作运营指标，不是模型置信度；
- `sourceIds`：人工最终稿中**仍然保留的 claim** 所引用的项目知识 ID，最多 10 条；不是“这次检索到的所有来源”，避免把未采用的候选误标为正样本；
- `query/queryTerms`：审核上下文中的业务请求，生成英文词和中文二元组；
- `decision/issues/note`：结论和可选问题标签；
- `split`：按最终内容哈希稳定分到 train/validation。

样本只保存业务草稿，不读取客户私信、个人邮箱或原始附件。`trainingOverview` 只返回摘要，不把 AI/客户正文返回给业务员。

## 自动校准

启用后，检索按以下顺序处理：

1. 项目、角色、发布版本、产品适用范围先按原逻辑过滤；
2. Python 本地向量/BM25/RRF/rerank 产生候选；
3. 只取最多 200 条最近“审核通过”样本，比较当前查询词项与样本词项；
4. 至少 2 个词项重合、覆盖率 ≥50% 才算相似；
5. 对样本采用的来源累加一个带时间衰减的权重，归一化后最多 **0.02**；
6. 只重排已通过准入门槛的候选，不改变 `accepted` 判定，不新增来源。

因此它不会把未达 rerank 阈值的内容推进来源列表，也不会跨项目或绕过产品/版本/角色边界。检索 trace 记录：

```json
{"feedback":{"enabled":true,"samples":12,"matched":3,"boosted":2}}
```

## 页面

管理员知识库新增第三个页签“质量与训练”，包含：

- 自动校准状态和启用/暂停按钮；
- 样本量、通过量、人工修改后通过量、可校准样本量；
- “通过稿中反复采用的来源”排行；
- 最近 12 条审核样本摘要（任务类型、结论、修改幅度、来源数量、业务请求摘要）；
- 安全边界说明。

业务员不需要额外操作：仍然只在原草稿审核页点通过/不通过。

```powershell
cd server
npx tsc --noEmit -p tsconfig.json
npm run test:knowledge-training
npm run test:mail

npm run test:knowledge-facts

cd ..\web
npm run typecheck
npm run build
```

本轮结果：

- `test:knowledge-training`：7/7
- `test:mail`：116/116
- `test:knowledge-retrieval`：18/18
- `test:knowledge-facts`：48/48
- 服务端/Web 类型检查通过
- Web 生产构建通过
- CI release gate 已加入训练测试及严格类型检查；本地通过后需等远端 Actions 复核

覆盖点：

1. 审核通过自动保存 AI 原稿、人工终稿、修改比例和来源；
2. 只把最终稿仍保留的 claim 来源标为正样本，未采用来源不参与训练；
3. 没有 AI 快照的旧稿不生成样本；
4. 自动校准默认关闭，启用后只对相似且通过的来源产生有界加权；
5. 不通过样本不参与加权，撤销审核撤出样本；
6. 只重排已接受命中，未接受候选不会被推入；
7. 训练概况/开关仅管理员可访问，只返回本项目摘要。

删除客户/草稿时的样本清理在 `customer.service` 与 `letter.service` 的删除路径中同步执行，避免客户数据删除后训练副本残留。

## 边界

- 这不是神经网络微调，也不自动替换本地 Embedding/Reranker 权重。它训练的是**可解释的来源排序先验**。真正微调需要更多真实样本、固定训练环境和独立离线评测，属于下一阶段。
- 样本量少于 3 条或没有词项重合时不产生任何加权；效果不应被当作普遍质量提升。
- 旧草稿如果没有 `aiSnapshot`，不参与训练；重新生成的新稿才会有基线。
- 自动校准只改变排序，不改变事实核验、发送门禁、产品过滤或人工审核。
- 页面展示的是样本和统计，不代表业务政策已确认；高风险价格/交期/认证仍由业务负责人审核。
- 当前没有自动发送真实邮件，也没有自动发布真实政策。
