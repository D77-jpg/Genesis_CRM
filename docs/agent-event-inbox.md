# P3 事件收件箱与自动草稿

入口：业务 Agent → 事件。规则按“项目 + 当前业务员”独立保存，默认关闭。启用后只处理启用时间之后新同步进 CRM 的来信，以及启用之后到期的本人客户跟进；不会启动邮箱收取服务，也不扫描历史邮件。不在其他项目/业务员名下执行。

来信事件：整理需求、事实来源与缺口，引用已发布的产品知识与版本，保存沿用原邮件线程的真实回复草稿。未关联客户的来信遵循现有管理员关联权限；普通业务员先等待管理员关联，关联到其客户后自动继续。自动生成的邮件仍由业务员打开、修改和发送。

到期事件：读取近期记录并准备跟进草稿；修改跟进时间、转交客户、停用账号或关闭规则后，未完成的旧任务停止。到期本身不会伪造“已联系”跟进记录。

每日最多 1–20 个自动任务，默认 5；每个任务 10,000–60,000 tokens 的保守调用上限，默认 30,000，失败和重试沿用已占预算。达到每日上限的事件留在收件箱等待额度；事件、日期和任务请求键去重，重启不重新生成相同草稿。

检测到退订、拒绝、退信或垃圾邮件信号时，停止该客户后续营销任务，并取消尚未进入投递的 Agent 邮件；保存草稿及送入 SMTP 队列前也重新检查。已交给 SMTP 的在途请求无法撤回。只有 SMTP 实际接受后才记录一次发送跟进；mock、草稿、失败与排队均不能当作已发送。原首封开发信仍沿用其已有去重规则。

任务收件箱可跳转到持久任务、邮件分析和原来信。已生成的摘要、产品事实版本和草稿可重新打开，关闭规则不会删除成果。邮件正文和附件视为不可信资料，不能改变工具权限或授权真实发信。
