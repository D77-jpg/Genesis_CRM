# 开发信审核：中英对照（2026-10-21）

## 目标

业务员在发送前能同时看到“实际会发出去的英文”和中文含义，避免因英文细节误判，同时不改变发送内容。

## 交互

- 发信弹窗的页签从“编辑 / 预览”扩展为“编辑 / 预览 / **中英对照**”。
- 对照页左右两栏：
  - 左：渲染后的英文原文（占位符已替换成客户资料），标注“实际发送”；
  - 右：自动生成的中文对照，包含主题与正文，标注“仅用于核对”。
- 窄屏（<lg）两栏上下堆叠；内容区各自限高滚动。
- 翻译失败时显示错误和“重新翻译”，不会阻断发送；翻译结果不写回草稿。

## 实现

- 新接口 `POST /api/agent/translate`，请求 `{subject?, body}`，返回 `{subject?, body}`。
  - 走当前项目的 AI 配置（`resolveAgentProvider`）；未配置时返回 503。
  - 提示词要求保留人名、公司名、产品名、邮箱、网址、数字、货币和 `{{占位符}}`，不增删事实。
  - 结构化输出（JSON schema），解析失败自动重试一次，仍失败返回 502。
  - 复用 `messageLimiter` 限流（30 次/分钟）。
- 前端在打开“中英对照”页签时请求一次；英文内容或主题变化后再次进入会重新翻译；翻译中显示骨架屏。
- 使用的是发送前渲染后的文本（`renderTemplate`），所以中文对应的是客户真正收到的内容。

## 验证

- 用 UncommonGoods 的真实草稿调用接口：
  - 主题 `A brief introduction` → `简要介绍`；
  - 正文完整翻译，保留 `Dave`、`Douglas Carlos` 等姓名，没有添加承诺。
- `typecheck`（前后端）与前端构建通过；接口实测 200。

## 成本

每打开一次且内容有变化，产生 1 次模型调用；仅浏览不编辑不会重复调用。

## 与审核弹窗改版的衔接（2026-10-22）

“中英对照”页签保留原行为，但被收进弹窗左列的“邮件内容”卡片里：模板导入、收件人、主题与“编辑 / 预览 / 中英对照”三页签位于同一张卡，右侧栏改为“审核结论 / 依据与风险 / 发送设置”。翻译仍然只是核对工具：不写回草稿、不影响审核结论的 `contentHash`（hash 取存储的主题与纯文本正文，不含译稿）。弹窗整体改版见 [customer-draft-review.md](./customer-draft-review.md)。
