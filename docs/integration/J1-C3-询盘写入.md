# J1 / C3：GlobalSite 询盘落入 CRM

日期：2026-11-06。权威字段定义在 [integration-v1.openapi.yaml](integration-v1.openapi.yaml)，流程见 [双方对接设计](globalsite-对接设计.md)。本阶段先 CRM C3，后 GlobalSite S7，两仓独立提交/PR，先合并 CRM。

## 方案与处理

选择新增 POST /api/integrations/v1/inquiries，scope inquiries:write（C2 已预选的保留权限正式开放）。旧 customers/upsert 不适合保存多条原文、附件、网站来源或通知；继续保持其行为不变。内部共用邮箱查找、补空字段以及 IntegrationIdempotency 租约/首次响应重放。

新联系人创建 pending Customer，来源 integration，leadSource=globalsite，标签 globalsite；不走需要额外转客户的 Prospect 流程，以便直接用现有客户归属、写信和 outcomes。邮箱匹配优先；非公共企业邮箱域名只有唯一客户时才合并。公共邮箱和歧义不按域名合并。现有客户负责人、阶段、外部系统引用及非空字段不覆盖。原始联系人、电话等完整保留在询盘；客户电话沿用既有60字符限制。合并到企业其他联系人时，回复邮箱仍用本条询盘邮箱。

新客户分配同组织/有项目权限的当前活跃项目创建者，或有效项目管理员；没有有效管理员时保持未分配。提醒收件人为有效项目负责人及已有客户负责人。提醒与询盘同事务持久化，CRM 顶栏展示未读站内提醒，可跳到客户详情。不会新增自动营销邮件。

顺序：服务认证/绑定项目/scope/共享每凭证限流 → 严格 zod 校验 → IntegrationIdempotency 占位 → MongoDB 事务内项目锁/客户匹配/询盘/附件任务/提醒 → 保存首次201结果。附件及外部网络请求不在主事务中执行。

## 数据与迁移

新增模型均通过 tenant-setup 注册 tenant 插件：

| 模型 | 主要数据 | 索引 |
|---|---|---|
| IntegrationInquiry | 项目/组织/客户、外部询盘ID、内容散列、加密原文、提交时间、站名、通知用户/已读用户、首次结果 | 唯一(organizationId,projectId,sourceSystem,externalInquiryId)，客户倒序、通知倒序 |
| IntegrationInquiryAttachment | 询盘/附件ID、状态、尝试次数/重试时间、owner/fence/租约、私有存储key、MIME/大小/错误码 | 唯一(organizationId,projectId,inquiryId,attachmentId)，任务状态/时间 |
| IntegrationInquiryLock | 项目/组织、锁版本 | 唯一(organizationId,projectId)，事务串行保护客户查重 |

Customer 增加 globalSiteSource、globalSiteLastInquiryAt、globalSiteLastSiteName、globalSiteLastPageUrl；已有来源保留，列表 globalsite 筛选也包含追加询盘的老客户。
Migration 20261106-009-globalsite-inquiries 只创建新集合索引及来源辅助索引，不改库名/旧集合名/旧数据。部署前运行 server npm run migrate；保留 C2 的 integration:credential -- migrate 前置要求。询盘事务需要副本集/兼容事务的 MongoDB 部署；本地验收使用临时 MongoMemoryReplSet，绝不连接已有用户库。

## 安全、幂等和附件

- 全部新业务查询显式限制组织与项目，私有询盘/附件再检查客户归属。新服务不允许无组织或 bypass 上下文接收询盘。
- IntegrationIdempotency 使用独立 inquiry 键命名空间和项目/端点/嵌套稳定内容散列。唯一业务键跨凭证轮换重放；相同 key/外部ID修改内容409；并发事务重试不新增客户或询盘。
- 原文/附件临时地址加密保存，并在解密时复核组织及询盘ID。私有响应去掉签名地址，仅提供鉴权附件下载路径；审计不记录正文、邮箱或URL。
- 附件最多3个×2MiB，后台持久租约领取；精确源白名单，固定公开IPv4 DNS答案、禁止重定向、15秒请求期限、大小/MIME/SHA256校验，复用storage.service。失败退避最多8次，失败或链接到期不撤销询盘。首次签名地址不因主接口幂等重放而刷新。
- GLOBALSITE_ATTACHMENT_ORIGINS 是部署者配置的精确来源白名单；默认不下载任意来源。GLOBALSITE_ALLOW_LOCAL 默认false，仅非生产且明确白名单的loopback联调可用，生产忽略它。
- 私有下载执行客户权限检查并强制attachment/nosniff/sandbox，无匿名读取内部路径。PDF仅文件签名检查，不宣称已杀毒。
- 回复入口为 CRM 用户会话/项目/客户授权，校验 EmailSuppression 后调用既有 sendLetter(saveAsDraft:true)。固定草稿幂等键，复用渲染/签名/合规链路，不调用发送。模板仅确认收到需求，不生成价格/交期/认证承诺；真正发送仍走既有人工审核和 mail-compliance。

## 契约与验证

新路径及 GlobalSiteC3* 单独冻结 globalsite-c3.json；legacy/C1/C2 快照不变。C2 的 available 布尔字段结构不变，只将 inquiries:write 标为已实现；S1 /globalsite/inquiries 仍未实现，不作别名。校验错误沿用 CRM 的422，鉴权/项目/冲突/限流错误沿用原有代码。

已执行 root typecheck/build/lint，集成66项、安全19项、健康5项以及 C2/C3 浏览器测试；其中C3真实HTTP/附件网络6项；两项浏览器测试各1项均通过。lint保留既有12条warning，本次不升级依赖。33项冻结拒绝回归保护原接口与新增契约。真实HTTP验证并发重放、换凭证业务去重、邮箱/域名合并、跨组织/项目拒绝、超长拒绝、附件失败保留存档、附件私有下载及禁发名单阻止草稿。

## 限制

未提供已过期附件URL的刷新端点、附件杀毒或数据保留/删除后台。站内提醒不等于外部邮件送达。域名合并是保守启发式，存在同域集团/代理商歧义时应由业务员人工检查。回复初稿为安全需求确认模板，后续可接入经事实校验的组织AI能力；本任务不使用真实AI密钥或付费验证。
