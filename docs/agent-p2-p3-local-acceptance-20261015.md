## 实际页面与模型验收

在本机 CRM 5173 的独立 Agent Acceptance Sandbox 项目中完成；项目无真实 SMTP/POP3 账户。API 仅启动 Agent 草稿任务观察器，未启动真实邮件投递或收件后台。模型使用本机当前已配置的服务，不在文档或提交中写入凭证。所有客户、来信、附件及产品参数都是虚构测试资料。

- 客户列表勾选五家 → Agent 批量准备草稿 → 勾选产品资料 v1 → 预览五家真实名单 → 确认。五家分别生成不同主题与正文，页面显示 5/5 待审核，保守预算占用 17,163 / 100,000 tokens。打开“审核草稿”会到对应客户的原草稿编辑器，不重复新增，不发送。
- 产品知识 v1 发布的参数为 MOQ 73 pcs、图稿确认后生产交期 19 天。页面再保存未发布 v2（999/99 的故意错误测试值），v1 仍然有效。后续真实模型回复仍引用 v1 的 73/19，没有采用 v2。
- 上传并从 Agent“产品知识”页读取实际 TXT 客户附件，正文与上传内容一致，并提示其为客户资料，不能变成我方供货承诺。实际 PDF/DOCX 提取、损坏/无文字文件、缓存越权另由隔离回归覆盖。
- 在测试项目启用当前业务员事件规则后写入一封合成询盘与一个新到期客户；观察器各创建一个持久任务，真实模型各保存一份询盘回复草稿/到期跟进草稿。回复保存原 Message-ID、In-Reply-To 与 threadId，收件箱能打开任务，再打开摘要与原草稿。
- 页面验收发现并修正了供应商交期混入客户需求，以及任务缺客户名称。增加合成询盘复验：客户需求数量仍为 120，客户交期未指定；我方 MOQ73/交期19天出现在供应商条款及回复中，显示知识 v1 来源。
- 当前兼容模型网关在复验任务中多次返回结构不合规结果，任务如实失败而没有写入邮件。增加已知同级字段误嵌套/双重转义换行的确定性兼容修复；其他不合规结果仍拒绝。该任务最终在五次上限内恢复为待审核，预算累计 17,175 / 30,000，仍仅一份草稿。**本次通过不代表模型网关每次都能无人干预成功；格式异常会保留失败步骤供重试。**
- 重启 API 后，已有五客户批次及事件任务保留，没有再创建相同事件或草稿。验收结束已从页面关闭测试规则；真实项目的规则保持默认关闭。
- 最终为八个不同客户保留八份不同待审核草稿、零非草稿邮件、零新增跟进记录。另有一份本地捕获的虚构模型响应用于诊断重放，只创建分析记录，不生成邮件。没有向真实客户发送验收邮件。

## 使用入口与边界

P2：客户列表 → 勾选 → Agent 批量准备草稿；Agent → 产品知识。最多 20 家，每家独立预算与任务，一家失败不会停止其余客户。

P3：Agent → 事件收件箱 → 核对范围后启用。仅处理新同步进 CRM 的来信及启用后到期事项；后台 POP/IMAP 收件同步是独立前置条件。业务员审核并实际发送后，SMTP 接受回执才写入发送跟进。退订/拒绝/退信会阻止后续 Agent 营销任务与未进入 SMTP 的排队投递。

附件目前不含 OCR、网页抓取或视频识别；业务技能为版本化固定流程声明；资料检索为当前项目的已发布产品知识/可读附件，不宣称已完成通用自主规划器或无限长期记忆。
