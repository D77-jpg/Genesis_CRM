# ADR-007：知识库本地运行、安全边界、恢复与迁移

状态：S7 单机本地工程交付，待用户PR/CI/合入；S4/S5 真实模型质量仍待验。起点 main 950e70f（S6 PR37），不改变 S0 门槛。

## 运行合同

- Mongo 是发布、权限、版本和任务租约的唯一权威。SQLite 与 Embedding 缓存均为可重建派生物，不用于恢复旧政策权限。
- 本地 ONNX 进程池最多2个进程、8个等待请求。排队最多30秒；进入模型前再次核对当前用户、项目、发布清单、代次和诊断标题的可见性；返回证据前仍有第二次核对。没有跨项目查询缓存或权限决定缓存。
- 模型文件/运行器身份改变会换进程并使旧代次明确落后。进程只缓存已校验的模型/分词器；SQLite连接、授权临时表、查询和候选不跨请求保留。重用文档向量仍限项目、访问范围、内容哈希和模型身份。
- 单调用120秒，进程最多32次调用/RSS超过1100MiB后轮换；操作系统限制每进程1536MiB/120秒累计CPU（Linux地址空间3GiB）。取消/超时终止实际子进程；三次基础设施故障熔断30秒。模型配置缺失和安全校验失败不回用旧向量。
- 解析仍为独立进程、隔离环境、180秒墙钟、格式/解压/输出限制；新增容量2、三次基础设施故障熔断30秒。不把恶意格式错误当模型服务熔断。业务待审核、失败和低质量OCR状态保持。
- 现有租约、围栏、幂等键和逐批检查点继续负责重启恢复；不把进程内队列作为持久任务队列。关闭服务先停调度器、终止进行中的解析并保留待重启任务、关本地推理池；强制退出遗留租约由现有恢复协议接管。
- LLM传输最大4并发；连续3次HTTP/传输/JSON基础设施错误熔断30秒，半开只允许一个探测。响应上限4MiB，超时覆盖读取响应体。传输层不自动重试或更换目的地；S5工作流的累计预算仍有效。错误码来自固定传输状态，不能把供应商任意错误内容作为日志字段。

## 监控及日志

管理员 `GET /api/knowledge-index/operations` 只聚合当前项目近7天解析、任务、草稿审核状态、引用核验结果、工具结果、模型用量/配置估价；不返回文档、邮件正文或查询文本。业务员和未登录用户不可访问，额外projectId参数被拒绝。

检索计数按项目/日/固定状态持久化，90天TTL；完全解析率和部分解析率分列，无答案率与服务故障分列。索引前10代次含时间、批次/重试与进度；精确发布/磁盘就绪检查继续使用现有 `GET /api/knowledge-index`。进程健康只代表接收请求的本机实例。估价不是供应商账单，失败/缺失usage的调用费用未知，不填成0。

默认应用/访问日志只允许固定事件、范围、数值、固定白名单错误码，移除原始消息/异常栈/URL/请求头/邮件/文档正文；每秒最多100条，每条最多1024字节。`CRM_LOG_FILE` 可设为仓库外绝对路径，最多3份、每份2MiB；控制台仍需要宿主保留策略。不要把外部程序任意标准输出重定向进业务日志。

HTTP管理员及维护命令输出 HEAD SHA 与工作区是否有源码改动。SHA不等于自动证明磁盘源码一致；正式验收须在干净、已合入提交上运行，并记录模型锁/运行器摘要。开发实测报告同时保存实际源码LF摘要。

## 本地组件操作

在正式仓库server目录执行。模型/解析环境沿用S0/S1/S3锁；不从业务系统下载或执行上传文件中的代码。尚无本地模型时按 `semantic/setup_runtime.py` 和 `parsers/setup_runtime.py` 操作说明准备固定公共资源，设置 KNOWLEDGE_PYTHON、KNOWLEDGE_TOKENIZER_DIR、KNOWLEDGE_MODEL_DIR、KNOWLEDGE_RERANKER_DIR；索引目录设 KNOWLEDGE_INDEX_DIR。不要把密钥写入文档。

单独维护知识库时，创建仓库外受保护的JSON配置，例如：

```json
{"mongodbUri":"mongodb://127.0.0.1:27017/REPLACE_DATABASE","projectId":"000000000000000000000000","actorId":"000000000000000000000000","receiptFile":"D:/Trade/local-logs/knowledge-status.json"}
```

必须填当前有效管理员和项目ID。CLI只接受回环Mongo；凭据通过配置文件而非命令行参数传入。

```powershell
npm run knowledge:maintenance -- preflight D:/Trade/local-private/knowledge.json
npm run knowledge:maintenance -- status D:/Trade/local-private/knowledge.json
npm run knowledge:maintenance -- rebuild D:/Trade/local-private/knowledge.json
npm run knowledge:maintenance -- worker D:/Trade/local-private/knowledge.json
```

- preflight只读计数/版本，不发布或迁移历史知识；status核验当前权限并保存报告；rebuild只申请新代次，由worker处理。
- worker只启动知识文档/索引调度，不导入CRM启动入口，不启用Agent生成、邮箱同步和发送队列。开发前台使用Ctrl+C；后台启动须隐藏窗口、保存回执，并核对PID与命令行属于该维护进程再停止。Windows强制停止按租约恢复处理。
- 正常CRM启动入口依然会启动既有邮件任务。独立验收禁止连接真实库后启动该入口；本阶段只用了临时数据库。
- 未就绪/落后：查看现有知识库“准备检索资料”和失败原因；检查锁定文件/目录/权限，申请新代次；不要强改activeGeneration。排队超时/容量满：保留持久任务并受控重试，不无限加并发。文件缺失/校验失败：恢复原文或重建索引，不能当无答案。

## 备份、恢复和边界

新增 `snapshot.ts` 用已安装的Mongo驱动真实读取BSON，使用严格EJSON保留ObjectId、Date、Binary等类型，压缩后AES-256-GCM加密。密钥单独生成/保存；新目录、清单/集合摘要、配置白名单/摘要、记录及解压规模限制。源指纹前后变化、活动任务、错误密钥、损坏内容均拒绝；恢复先完整认证/校验再写空目标库，绝不覆盖已有数据库。

**这个新工具只接受 `s7_fictional_<12hex>` / `s7_restore_test_<12hex>` 的演练库。** 不是未经验证的真实库恢复按钮。演练通过 `npm run test:knowledge-operations` 实际创建/销毁隔离Mongo，备份原始文件、双知识版本、任务状态和配置，恢复到空库，逐字节核对原文及全部集合，再从Mongo用真实模型重建丢失的SQLite并跨语言查询。

当前备份模式要求所有写入者已停止，前后摘要检查不是事务快照证明；同时发生且恢复原状的写入无法检出。不能对运行中CRM声称点时一致性。现有 `scripts/mongo-backup.cjs` 仍是通用Mongo工具入口；本机没有mongodump/mongorestore，已有模拟工具单测不能算真实生产恢复。上线前另行安装工具、停写/副本集一致性方案、独立加密备份介质、保留/权限策略和目标环境演练。

派生索引采用重建而不是复制正在WAL写入的SQLite。配置备份包含模型/重排锁和运行器文件摘要；大模型权重按锁重新准备并校验，不把临时上传资料发送到外部存储。

## 兼容、预检、升级与回滚

1. 先核实main含S0–S6，记录SHA/模型身份，停写并做独立备份。preflight统计草稿、发布版本、任务与代次；原82条草稿、客户和人工改稿均不迁移、不发布、不删除。
2. 新增监控集合为可选附加数据，不改变旧知识/草稿schema必填字段。已发布修订内容不改；历史解析映射继续按S1显式预览操作，不自动映射。
3. S7运行器摘要改变，使S6代次不再兼容；管理员申请新代次/启动知识worker。完整清单与模型校验通过才切换；失败或中断保留旧指针但对不兼容查询明确阻断。
4. 同版本内回滚代次只使用既有rollback入口，重新核对当前发布清单、模型、权限和磁盘摘要。知识停用/失效后不能回切旧政策。
5. 代码回滚由用户按PR流程操作，不回滚Mongo业务数据。旧代码忽略新增监控集合；按旧代码身份重新验证或重建派生索引，不手动覆盖知识修订。恢复练习只到新库，审阅通过后再独立安排正式切换。
6. 本地索引路径不能由不同主机各自共享同一Mongo活动指针冒充高可用。多机/跨机滚动升级未支持；采用单机知识worker与同机索引，异机缺失会安全失败。此限制阻止声称已经可直接多节点生产部署。

## 最终验收入口

S7实测、失败保留与资源见 knowledge-s7-results/README.md。S8仍须在全部代码合入、干净SHA上重跑冻结质量和完整页面链路；补齐S4授权网关44项（22开发/22首次保留）及S5五类真实模型文案质量。不能把本地子进程/回环HTTP测试算供应商质量。

原生解析库/ONNX进程有系统资源限制和Python网络审计，但没有Windows AppContainer/独立低权限账户或容器文件系统隔离；不能宣称抵抗原生库漏洞的完整OS沙箱。真实资料本地处理，无新外传。生产TLS/域名/凭据轮换/备份介质/分布式索引/更大规模与真实发信另列上线待办。
