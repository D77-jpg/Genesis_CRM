# Agent 首封开发信联动（2026-10-13）

## 操作流程

1. 打开目标客户详情，在业务 Agent 输入“帮我给这个客户写第一封开发信”。
2. 系统读取有权访问的客户资料，保存可恢复的分析与草稿，自动打开该客户的写信窗口，填入主题和正文。业务员核对、修改后自己点击发送；也可以取消或手动存草稿。
3. SMTP 接受邮件后，系统自动新增“首封开发信已发送（SMTP 已接受，等待客户回复）”跟进，包含主题、收件人、实际发送时间和业务员。SMTP 接受不代表收件人已阅读。

历史对话提供“打开首封开发信”入口。发件署名优先使用当前业务员的个人发件账户名称，未知价格、交期、联系人不会补造。缺少收件地址或未验证发件账户时，仍能准备草稿，实际发送沿用已有页面校验。

## 实现约束

- 只有明确的用户写信命令进入联动；客户备注、邮件正文和模型返回内容不能触发系统动作。全局会话提示先打开目标客户。
- 模型工具保持只读。生成动作只保存 Agent 草稿，不创建已发送开发信、不写“已发送”跟进。
- 草稿读取与邮件关联均验证当前用户、项目和客户；客户转移后原业务员不可访问。
- 正文按纯文本转义，段落正常排版，模型输出的 HTML 不执行。
- 邮件队列在成功后的结果核对阶段写跟进。草稿、取消、失败、模拟投递不生成真实已发送跟进；相同草稿的任务重试和重复核对只创建一次。
- 手动保存开发信草稿、再打开并发送时保留 Agent 关联。

## 验证

- 服务端类型检查通过；前端类型检查与生产构建通过。
- Agent 回归 38/38，包括仅生成不发送、历史恢复、用户命令判断、署名采用实际邮箱账户以及访问隔离。
- 邮件与 POP3 回归 94/94，包括 SMTP 失败不写跟进、成功后写一次、并发重复核对、关联归属验证、模拟发送不写真实跟进。
- 前端字段与草稿转换回归 5/5，包括 HTML 转义、错客户拒绝、段落间距。
- 安全回归 5/5。
- 本地已登录 CRM 页面输入指令后，真实 AI 生成主题与英文正文，并自动打开客户写信窗口。验收到业务员发送入口；没有向真实客户发送邮件。真实 SMTP 成功后的自动跟进使用隔离数据库和受控投递结果验证。

页面复验发现并修复了正文署名与实际发件账户不一致，以及编辑器多余空行的问题。真实模型复验中有一次返回格式不合规，系统拒绝该结果且没有打开写信页、发送邮件或新增跟进；再次生成后成功。截图中的 SMTP 成功发送仍需业务员手动完成。
