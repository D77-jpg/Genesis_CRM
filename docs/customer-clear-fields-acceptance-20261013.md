# 客户可选字段清空修复

日期：2026-10-13。

问题：客户详情行内编辑把清空后的值转换成空补丁；编辑弹窗把空值转换成 undefined；后端客户更新校验再次把空字符串转换成 undefined，服务层因此保留旧值。用户清空需求备注后，保存或重新读取时旧内容恢复。

修复：行内编辑和编辑弹窗明确提交空字符串，客户更新接口保留清空值。未传字段仍保留原值，新建与导入仍沿用原有空值归一化。适用于需求备注、普通备注及客户可选文本字段；邮箱空字符串不会进入非空邮箱唯一索引。来源选择“未设置”也可清空。

验证：
- 92 项隔离邮件/客户接口测试全部通过，0 跳过，包括清空后重新读取、未传字段保留、两个客户清空邮箱、字段长度和跨项目权限。
- 2 项前端提交载荷测试通过，覆盖行内编辑与编辑弹窗，确保空值经过 JSON 传输仍存在。
- 服务端类型检查和前端生产构建通过。
- CI 增加前端清空字段提交回归门禁。

真实客户数据清空仅针对用户截图指向的 Studio K36 需求备注，通过本地正式接口处理并保留操作前备份；其他字段和其他客户保持原值。操作结果见本地验收输出，不将真实客户资料提交到仓库。
