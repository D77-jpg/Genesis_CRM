# ADR-004：条件事实与邮件事实核验（S4 工程交付／质量待验收）

起点：main `57a3adc`（已含 S3 PR #34）。本阶段沿用 CRM、知识修订、个人邮箱权限、索引与人工发送流程；不接入独立知识库平台。

## 条件合同

KnowledgeTerm 可增加 scope：精确产品、工艺、采购数量区间及开闭边界/单位、交期起算点、生效失效、排除项、肯定/否定及证书编号/签发方/覆盖产品/有效期。原数值、币种、计价单位、参考/确认程度及完整条件文字保留。没有 scope 的历史条款不会被自动升级成已确认承诺；不修改旧修订与82条真实草稿。导入仍只产生待审草稿。

ConditionalEvidence ID 包含 source/version/原发布条款编号；发布正文保留精确 Unicode 区间、内容哈希和 S1 sourceRefs。检索窗口不冒充原文位置，手工确认条件定位到 publication_term，不能伪称来自原 PDF 某一行。

## 客户专属约定

新增 CustomerAgreement 是当前客户内的最小可审核版本记录：管理员明确来源、全文、逐项条件与有效期后确认。客户需求、邮件或自由备注不推断为协议。业务员只读当前可见客户的有效已确认版本；新草稿不覆盖已确认版本，停用立即阻断。双方真实法律效力仍由业务负责人确认。

已接受报价只有精确客户、产品、显式数量、型号（如存在）与有效期匹配才提供价格事实。自由交期/付款/MOQ文字不直接升级为结构化承诺。专属记录不进入项目通用索引，也不静默覆盖冲突的一般政策。

## 核验合同

检索相似不等于适用。服务端先判条件/时效，再对同一实际请求下不兼容的来源报告冲突。普通事实调用现有配置模型做受约束蕴含核验，返回逐段结论和精确引用；模板、客户需求不作为我方依据。引用须匹配授权正文的 Unicode 区间。关键承诺另做确定性硬门禁，仅允许保留含完整值/单位/条件的已确认事实卡，模型判断不能放宽。

最多两次核验、一次整封重写；仍无法支持时生成连贯的安全部分答复和待确认项，不用大量正则删句拼接。Mock Provider 不冒充语义核验；服务失败、未启用和缺资料分别记录，回退稿标为不完整。每次模型调用复用现有输入/输出上限、超时、额度与任务预算。核验前后重新检查依据/权限，旧稿不被静默改写。纯翻译/润色检查数值在各政策主题中的对应关系，并另行检查原意/否定；无法核实则明确失败。

## 首个工程检查点

独立 MongoMemoryServer 虚构项目/客户：20 项条件/约定/核验门禁测试、原知识15项回归与服务端类型检查通过。语义测试使用可控核验器，验证协议与故障边界，不代表真实模型质量达标。完整界面、真实模型样本、回归及 S0 质量门槛测量仍在进行，S4 尚未交付完成。不修改真实客户、不发真实邮件、不发布真实草稿。

## 页面与二次审核检查点

- 知识条件可填写数量边界、产品/工艺、物流范围、金额类型、起算点、证书范围；已核对范围默认折叠，修改任一条款或条件会清除旧确认状态，需重新核对。
- 客户详情增加专属约定的草稿/确认、有效期、历史与停用。草稿审核显示逐项支持/矛盾/待确认、精确引用与适用性。
- 写信页“核对当前编辑内容”验证当前主题及正文，不覆盖原稿/原证据；复核记录按 requestKey+正文哈希幂等、检查客户权限与依据变化、保留最多20次（达到上限要求另存新稿，而不是删除旧记录）。依据过期或撤权不送给模型。
- 44项新虚构语义样本已冻结，开发/保留各22；默认评测只校验，不发外部请求。当前模型配置为既有网关，用户已明确授权这44项虚构样本仅发往当前网关 http://124.222.23.70:18744。开发组22项实际调用均未取得模型结果，诊断为连接拒绝；原始失败报告保留，保留组未运行，不计语义质量通过。
- 28项专项（含本地真实HTTP适配器协议测试，但不冒充真实模型语义质量）、Agent62、邮件/POP3 96、安全5、模板3、随手记3、AI配置6及前端33项/构建已通过。真实S3检索13项通过；S2索引最终23/23；初次旧fixture缺少S4结构化范围时安全地未放行73/19，补齐独立fixture后重跑通过，不放宽门禁。此处尚不标记S4完成。


## 业务操作

1. 知识库中编辑政策条目，在每项交易条款填写值/币种/单位和原始条件；展开“适用范围与边界”，核对产品、工艺、数量区间（含开闭边界）、交期起点、有效期及证书范围，再勾选已核对。修改范围/条件会清除确认。原有无scope条款仍可查历史，但不自动当成已确认承诺；不批量升级82条草稿。
2. 客户详情的“客户专属约定”由管理员登记明确来源、全文、逐项条件和期限，保存待审或确认；新草稿不替代当前确认版。业务员只能看到当前可见客户的有效确认版。停用和知识/报价更新会让旧草稿提示依据变化。
3. 客户分析、邮件线程及业务回答走明确知识检索及适用性门禁，普通事实调用现有配置模型核验；纯翻译/润色只使用原文核对，不无关检索。客户资料仅支持收件人个性化，不成为供应商事实。生成后内部审核展示来源版本、逐项结论、精确引用、问题覆盖及缺口。
4. 写信页人工改主题/正文后点击“核对当前编辑内容”；异步完成前继续编辑，旧结果不会显示为新内容的结果。复核与原生成证据分开保存，不改正文；需按最新依据重写时生成另一份草稿。只有业务员原有发送操作可以发送。

## 可复现检查

在server目录执行 `npm run test:knowledge-facts` 和 `npm run eval:knowledge:facts`；后者默认仅校验冻结数据。真实评测显式使用：

```powershell
npm run eval:knowledge:facts -- --live --split dev --authorized-origin http://124.222.23.70:18744 --dataset-sha256 0c6a23356b59b105e19de0e2c5b29c9620f004982f2b811cec9a8c1120a99bc0 --out <新的开发报告路径.json>
```

仅在开发质量通过后将split改holdout，使用全新路径首次测保留组；不得覆盖首轮，不能改目的地或资料范围。连接恢复前不必重复把失败请求算成质量测量。完整验证见[结果](knowledge-s4-results/README.md)。

## 仍有边界

- 普通事实依赖当前配置模型的受约束判断，生成和核验可为同一模型，不能保证消除所有同源错误。无真实质量结果前必须人工审核。
- 关键承诺采用完整事实卡原样输出，确保值/条件不被改写；代价是文风偏正式，原始条件为中文时会保留中文，管理员若要英文客户邮件应填写审核后的英文条件，不能让系统私自翻译成新承诺。
- 产品/工艺/单位用精确规范值，未做所有别名/单位换算；语义相近不能绕过范围门禁。排除项和不明确条件转待确认；条件同义不同写法也可能保守地报告冲突。
- 约定最多100条、单约定100修订、单稿20次复核，达到上限明确提示而非静默裁剪。逐段核验64段、正文2万字符、模型输入最高4.8万字符且服从既有全局预算；超限给部分稿或显式故障，不截断条件。
- 手工条款位置为发布条目/报价项目/约定条目，不伪造PDF坐标；S6再完善引用跳转/差异体验。S5统一五类邮件、S7规模与多机、S8最终整体验收尚未完成。
