# ADR-004：条件事实与邮件事实核验（S4 开发中）

起点：main `57a3adc`（已含 S3 PR #34）。本阶段沿用 CRM、知识修订、个人邮箱权限、索引与人工发送流程；不接入独立知识库平台。

## 条件合同

KnowledgeTerm 可增加 scope：精确产品、工艺、采购数量区间及开闭边界/单位、交期起算点、生效失效、排除项、肯定/否定及证书编号/签发方/覆盖产品/有效期。原数值、币种、计价单位、参考/确认程度及完整条件文字保留。没有 scope 的历史条款不会被自动升级成已确认承诺；不修改旧修订与82条真实草稿。导入仍只产生待审草稿。

ConditionalEvidence ID 包含 source/version/原发布条款编号；发布正文保留精确 Unicode 区间、内容哈希和 S1 sourceRefs。检索窗口不冒充原文位置，手工确认条件定位到 publication_term，不能伪称来自原 PDF 某一行。

## 客户专属约定

新增 CustomerAgreement 是当前客户内的最小可审核版本记录：管理员明确来源、全文、逐项条件与有效期后确认。客户需求、邮件或自由备注不推断为协议。业务员只读当前可见客户的有效已确认版本；新草稿不覆盖已确认版本，停用立即阻断。双方真实法律效力仍由业务负责人确认。

已接受报价只有精确客户、产品、显式数量、型号（如存在）与有效期匹配才提供价格事实。自由交期/付款/MOQ文字不直接升级为结构化承诺。专属记录不进入项目通用索引，也不静默覆盖冲突的一般政策。

## 核验合同

检索相似不等于适用。服务端先判条件/时效，再对同一实际请求下不兼容的来源报告冲突。普通事实调用现有配置模型做受约束蕴含核验，返回逐段结论和精确引用；模板、客户需求不作为我方依据。引用须匹配授权正文的 Unicode 区间。关键承诺另做确定性硬门禁，仅允许保留含完整值/单位/条件的已确认事实卡，模型判断不能放宽。

最多两次核验、一次整封重写；仍无法支持时生成连贯的安全部分答复和待确认项，不用大量正则删句拼接。Mock Provider 不冒充语义核验；服务失败、未启用和缺资料分别记录，回退稿标为不完整。每次模型调用复用现有输入/输出上限、超时、额度与任务预算。核验前后重新检查依据/权限，旧稿不被静默改写。纯翻译/润色检查数值在各政策主题中的对应关系，并另行检查原意/否定；无法核实则明确失败。

## 首个工程检查点

独立 MongoMemoryServer 虚构项目/客户：20 项条件/约定/核验门禁测试、原知识15项回归与服务端类型检查通过。语义测试使用可控核验器，验证协议与故障边界，不代表真实模型质量达标。完整界面、真实模型样本、回归及 S0 质量门槛测量仍在进行，S4 尚未交付完成。不修改真实客户、不发真实邮件、不发布真实草稿。
