# 自动开发（Outreach Autopilot）

## 目标

用现有客户和导入名单，按第 1 → 3 天 → 第 2 封 → 7 天 → 第 3 封的节奏自动完成开发信。
每个业务员使用自己的已验证发件邮箱，默认每个邮箱每天最多 20 封。

## 运行方式

1. 业务员（或管理员选择业务员）在「自动开发」页开始自动开发。
2. 管理员可以在「执行账号」里切换业务员；每个账号只读取自己负责的客户，并使用自己已验证的发件邮箱。
3. 系统只为符合以下条件的客户建立队列：
   - 客户归属该业务员；
   - 有有效邮箱；
   - 状态为「待开发」或「已联系」；
   - 未回复、未退订、未退信、未明确拒绝、未流失；
   - 开发进度不足 3 封。
3. 到发送时间且队列项到期时：
   - 没有下一封草稿，先用现有 Agent 工作流生成**单封**草稿；
   - 草稿通过依据校验后，标记为自动批准；
   - 通过现有 SMTP 队列发送，再按 3/7/14 天节奏排下一封。
4. 回复、退订、退信、拒绝、删除客户、邮箱失效都会停止自动发送。

## 安全边界

- 只使用业务员本人的已验证邮箱；不会借用管理员或其他人的邮箱。
- 单封草稿生成，不一次预生成三封，避免回复/资料变化后继续发旧内容。
- 发送前检查：
  - 客户仍属于该业务员；
  - 没有受保护邮件信号；
  - 草稿存在知识依据，且内容指纹未被修改；
  - 草稿不是人工「不通过」或待核实状态；
  - 没有未替换的占位符；
  - 当前邮箱、域名和每日额度允许发送。
- 结构性依据问题（依据过期、冲突、检索失败）仍然阻止自动发送。
- 自动批准记录为 `automation:<campaignId>`，不会被当作人工审核。
- 暂停总开关会立即停止创建新的自动发送任务；已经交给 SMTP 队列的邮件由现有投递队列处理。

## 默认限制

| 项目 | 默认值 |
|---|---|
| 每天/邮箱 | 20 封 |
| 每域名/24 小时 | 3 封 |
| 发送时段 | 工作日 09:30–17:30 |
| 时区 | Asia/Shanghai |
| 节奏 | 3 / 7 / 14 天 |
| 收件人状态 | pending / contacted |
