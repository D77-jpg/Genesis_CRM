# P3 安全测试与外部渗透测试清单

## 1. 结论边界

本仓库已完成**内部安全基线**：接口鉴权、CSRF、租户隔离、Cookie 属性、安全响应头、公共接口信息边界、依赖审计，以及既有上传/邮件/权限测试。内部测试通过不等于外部渗透测试通过；**正式公开上市前仍需由独立第三方完成渗透测试并复测高危/中危问题**。

测试日期：2026-11-04。对象：本仓库当前 `feat/p0-cookie-session` 分支。环境：本地测试 Mongo/内存 Mongo，非生产。

## 2. 内部基线命令

```powershell
npm run test:security --prefix server     # 既有安全测试 + P3 基线，共 19 项
npm run security:audit --prefix server    # 生产依赖 audit（high/critical 阻断）
npm audit --omit=dev --prefix web         # 前端生产依赖 audit
npm run test:p3 --prefix server           # 迁移 + 营收主流程 E2E
```

本次结果：

- `test:security`：19/19 通过（P3 新增 6 项：安全头、未登录拒绝、CSRF 与 Cookie、租户隔离、公共套餐接口、错误不泄露栈）。
- 服务端生产依赖 audit：**0 vulnerabilities**。
- Web 生产依赖 audit：仅 1 个 low（Quill 2.0.3 HTML 导出 XSS），无 high/critical/moderate；服务端对所有外发 HTML 使用 `safeMailHtml` 清洗，编辑器只在受信内部使用，风险已记录并持续跟踪上游修复。
- 前端路由已升级 React Router 7.18.5；旧 `react-quill`（Quill 1.3.7）已替换为 `react-quill-new`（Quill 2）。
- 开发依赖仍有 ESLint/minimatch 的 moderate DoS 报告，不进入生产包；在工具链升级窗口处理。

## 3. 外部渗透测试范围

### 3.1 认证与会话

- 登录枚举、密码喷洒、账号锁定绕过、2FA 绕过/重放、验证码暴力破解。
- Access/refresh Cookie 的 `HttpOnly`、`Secure`、`SameSite`、作用域、过期、轮换与撤销。
- CSRF：跨站表单、JSON content-type、SameSite 边界、CORS 预检绕过。
- 会话固定、退出后重放、并发 refresh 竞态、密码重置令牌一次性。

### 3.2 授权与租户隔离

- 水平越权：遍历 customer/letter/mail/quotation/attachment ID，跨项目读取/写入/下载。
- 垂直越权：viewer 执行写操作、project_admin 跨项目、org admin 跨组织、平台管理员接口边界。
- `X-Project-Id` 伪造、缺失、重复 header、空项目、已删除项目。
- 批量接口（导入、批量状态、导出、报价）逐条资源授权。

### 3.3 注入与文件

- NoSQL 注入（`$ne`、`$where`、对象代替字符串）、正则 ReDoS、超长/嵌套 JSON。
- HTML/邮件模板注入、存储型 XSS、CSV/Excel 公式注入、开放重定向。
- 上传：双扩展名、MIME 伪造、zip bomb、路径穿越、SVG/HTML、跨租户附件读取、对象存储签名 URL 越权。
- 邮件解析：恶意 MIME、超长 header、附件炸弹、SSRF（图片/链接抓取）、退订/退信伪造。

### 3.4 AI 与知识库

- Prompt injection 跨项目取数、越权工具调用、系统提示泄露、知识库文档中的间接注入。
- 模型密钥/供应商配置读取、流式响应中的其他租户数据、日志中的敏感内容。
- 知识库上传文档的解析器沙箱、宏/脚本、超大文档 DoS。

### 3.5 业务与基础设施

- 发送频率/配额绕过、退订抑制绕过、批量导入资源消耗、报价金额篡改（客户端传 amount）。
- 限流键伪造（`X-Forwarded-For`）、缓存投毒、Host header、CORS 反射、TLS 配置。
- Docker/Compose 暴露面、Mongo 未授权、备份文件下载、日志注入、错误页信息泄露。
- 依赖供应链：lockfile、镜像、CI secrets、GitHub Actions 权限。

### 3.6 明确不在范围（需合同约定）

- 物理入侵、员工社工、钓鱼演练；
- 第三方邮件服务商/S3/AI 供应商自身基础设施；
- 客户自有 SMTP/IMAP 服务器；
- 拒绝服务压测超出约定阈值；
- 生产数据导出/修改。

## 4. 执行规则（Rules of Engagement）

1. 测试只在 staging 或专用测试组织进行，使用合成数据；禁止对生产发起扫描/利用。
2. 提供测试窗口、白名单 IP、测试账号（admin/project_admin/user/viewer 各一）和联系人。
3. 禁止破坏性操作；发现可写入漏洞时立即停止并保留最小 PoC。
4. 严重问题（数据泄露、RCE、认证绕过）发现后 1 小时内通知；其他按报告周期。
5. 测试方不得保留、复制或外传客户数据；结束后删除本地副本。
6. 复测范围包括所有 high/critical 及双方确认的 medium。

## 5. 交付物与验收

报告需包含：执行摘要、风险评级（CVSS 3.1）、影响、复现步骤、请求/响应、证据、修复建议、复测结果。验收标准：

- 0 个未修复 critical/high；
- medium 有明确修复计划或书面风险接受；
- 复测通过并出具签字确认；
- 修复不引入回归（`test:security`、`test:p3`、构建通过）。
