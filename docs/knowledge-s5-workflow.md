# ADR-005：五类销售邮件的持久证据工作流（S5）

起点main b4e286a（S4 PR35已合入）。用户明确要求进入S5；S4真实模型质量仍因获授权网关拒绝连接而待验，不降低或改写S0/S4指标。S5工程可继续，最终质量不能据此通过。

沿用现有AgentTask租约/暂停/重试、客户分析、线程分析、批量和事件任务；不引入第二套调度平台。kind扩展为首封开发信、询盘回复、报价说明、样品回复和客户跟进。输入来信只决定需求，不能提升权限或发信。

任务内workflowRecords保存版本化的步骤状态、输入哈希、时间、耗时、尝试/复用次数、工具类别和结果；完整payload只在数据库检查点中使用，任务DTO不暴露正文/提示词。read_context→extract_requirements→load_rules→retrieve_0（最多2次补查）→assess_evidence→generate_email→audit_claims→原保存草稿/核对→handoff。模型生成与核验可按精确输入哈希复用；读取权限、现行规则、发布状态和检索永远重查。

恢复时读当前账号角色/项目、客户/个人邮箱权限，并重新计算授权客户/邮件/报价/约定/知识输入指纹。变化时使用新epoch和幂等键，旧分析/草稿保留，不改写人工编辑；最多3次epoch更新。推理期间发生变化会阻止保存结果，需重新发起；无法证明可用性不默用缓存。

每次领取最多180秒，沿用90秒租约/10秒心跳；任务最多5次领取。每任务最多30次实际步骤执行，最多60条跨epoch步骤记录；模型步骤按120秒、其他步骤按1秒保守累计预留，累计60万毫秒上限，失败/中断不退款。这是保守处理预算，不是实际耗时；实际耗时单独记录。沿用累计tokenBudget和日额度，核验最多2次检查/1次整封重写；无发信工具。

规则稳定加载当前项目已发布/有效/有权限最多4条；主题驱动首查，按仍缺失的政策主题最多2次补查，不由模型任意扩展。16来源/4.8万字符证据上限，超出明确失败，不切断条件。已知采购数量/目的地来自可访问客户来信，冲突数量不擅选；模糊历史和更早内容不保证自动归并。

首个工程检查点：11项S5独立测试（包括真实终止worker后另进程恢复，未重复生成）及原Agent62通过；类型检查通过。模型输出为受控fixture，不等于真实事实支持质量。完整页面、回归、安全扫描与限制记录继续更新。


## 后续检查点

- 五类邮件各自真实终止worker并换进程恢复通过，20项专项覆盖私有邮箱撤权、推理期间知识变更、待审核时客户资料变更、输入哈希复用、重试上限和多问题真实补查。
- 用户明确继续后才重新准备变更过的资料；未变的输入可复用生成检查点，预算不回退。任务摘要和审核入口在资料变化时隐藏，避免把旧结果当当前结果。
- 首封开发信不因旧来信提到价格/MOQ就主动添加承诺；已知数量/目的地不再重复询问。报价、样品、跟进使用各自任务语义与安全主题，不把全部邮件都标成开发信。
- 页面五类均已生成并打开审核，未配置发信账号的独立样本保持不可发送。核验步骤完成与事实质量通过分开显示，部分稿明确仍需人工确认。最终截图和安全/真实组件结果继续归档。


## 操作与兼容

- 客户页面打开销售助手，可直接选首封、报价说明、样品回复、跟进；询盘在当前邮件线程中选择“回复这封询盘邮件”。快捷“分析客户并起草”“整理来信并准备回复”也进入同一可恢复任务，历史分析记录/API仍保留。
- 在“待办→处理详情”查看本轮证据步骤、耗时、复用及历史事件。部分稿明确显示“仍需人工确认”，不把步骤完成等同事实质量通过。准备好后打开写信页审核，原发送规则不变。
- 暂停/取消阻止后续步骤；已在网络中的请求可能结束，但没有当前租约就不能继续核验/保存。恢复会重读授权数据。无效模型输出不持久为已完成生成缓存，重试可以获得新输出。
- 资料变化后的待审核任务提示“重新准备”，旧稿保留并有历史入口。旧稿发送不完成新稿任务；投递保留agentDraftId，只新增可选字段，旧记录不迁移，不修改82条真实草稿。已有首封跟进幂等键和v1任务四个completedSteps仍兼容。
- 独立测试：server下 `npm run test:knowledge-workflow`；真实本地组件另跑 `npm run test:knowledge-retrieval`，必须使用固定模型/重排与Python环境。冻结S0/S4评测数据、标签和门槛均不变。

## 最终本地结果与明确限制

功能5e495b0，23项S5专项（五类均实际进程终止/替换恢复）、14项真实本地检索及相关回归通过；[实际记录与截图](knowledge-s5-results/README.md)已归档。获授权网关仍拒绝连接，真实生成和语义质量未验收，不冒充S4达标。

需求整理是有限规则，不是完整多语言语义消歧器；互相矛盾的数量保留未知，MOQ提问不等于采购数量，不能从客户要求推断我方承诺。只处理本轮授权有界历史：客户分析最多20封各方向往来/30条时间线，线程最多200封各方向；单条历史正文沿用既有上限，更早/被裁剪内容不保证完整归并。客户资料/附件不自动成为已确认供应商政策。

恢复指纹最多500条各类往来/报价、100条约定、1000条发布记录；达到边界明确拒绝，不把未检查部分说成未变化。任一发布资料编辑或权限范围改变会保守触发重读，可能包含与本稿无关的变更；大量任务频繁重验的数据库成本归S7优化，当前没有1万独立片段/并发2完整性能通过声明。

规则最多4条、业务证据最多16来源/4.8万字符、步骤payload最多16万字符，超限需拆分任务；不截断交易条件。每任务累计30次步骤执行/60条跨epoch记录，最多3次新epoch、5次领取。每次180秒截止会持久失败并fence旧写入；单次网络请求仍受既有HTTP超时且未实现供应商侧撤回。累计60万毫秒是保守预留（模型步骤12万/其他1000），不当作真实耗时。失败/中断不重置token预算；崩溃残留日配额预留保守保留，回收策略在后续运维阶段完善。

当前生成/核验可使用同一配置模型；受控语义fixture和模拟投递回执不是LLM质量或真实送达率。S4门槛、新S5真实邮件文案、S6治理、S7规模/多实例及S8最终业务验收均不能靠本阶段工程测试数代替。
