# ADR-005：五类销售邮件的持久证据工作流（S5）

起点main b4e286a（S4 PR35已合入）。用户明确要求进入S5；S4真实模型质量仍因获授权网关拒绝连接而待验，不降低或改写S0/S4指标。S5工程可继续，最终质量不能据此通过。

沿用现有AgentTask租约/暂停/重试、客户分析、线程分析、批量和事件任务；不引入第二套调度平台。kind扩展为首封开发信、询盘回复、报价说明、样品回复和客户跟进。输入来信只决定需求，不能提升权限或发信。

任务内workflowRecords保存版本化的步骤状态、输入哈希、时间、耗时、尝试/复用次数、工具类别和结果；完整payload只在数据库检查点中使用，任务DTO不暴露正文/提示词。read_context→extract_requirements→load_rules→retrieve_0（最多2次补查）→assess_evidence→generate_email→audit_claims→原保存草稿/核对→handoff。模型生成与核验可按精确输入哈希复用；读取权限、现行规则、发布状态和检索永远重查。

恢复时读当前账号角色/项目、客户/个人邮箱权限，并重新计算授权客户/邮件/报价/约定/知识输入指纹。变化时使用新epoch和幂等键，旧分析/草稿保留，不改写人工编辑；最多3次epoch更新。推理期间发生变化会阻止保存结果，需重新发起；无法证明可用性不默用缓存。

每次领取最多180秒，沿用90秒租约/10秒心跳；任务最多5次领取。每任务最多30次实际步骤执行，最多60条跨epoch步骤记录；模型步骤按120秒、其他步骤按1秒保守累计预留，累计60万毫秒上限，失败/中断不退款。这是保守处理预算，不是实际耗时；实际耗时单独记录。沿用累计tokenBudget和日额度，核验最多2次检查/1次整封重写；无发信工具。

规则稳定加载当前项目已发布/有效/有权限最多4条；主题驱动首查，按仍缺失的政策主题最多2次补查，不由模型任意扩展。16来源/4.8万字符证据上限，超出明确失败，不切断条件。已知采购数量/目的地来自可访问客户来信，冲突数量不擅选；模糊历史和更早内容不保证自动归并。

首个工程检查点：11项S5独立测试（包括真实终止worker后另进程恢复，未重复生成）及原Agent62通过；类型检查通过。模型输出为受控fixture，不等于真实事实支持质量。完整页面、回归、安全扫描与限制记录继续更新。
