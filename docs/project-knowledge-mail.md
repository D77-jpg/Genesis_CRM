# 项目知识库与邮件依据审核

## 使用入口

当前项目 → 左侧「知识库」，或销售助手 → 工具 → 项目知识库。管理员维护与发布；业务员只能查看当前有效的已发布资料。切换项目后列表、检索、草稿及客户报价都按项目重新授权。

分类为公司与品牌、产品与定制、交易政策、质量与合规、销售规则、常见问题。每条保存标题、正文、关键词、产品、适用条件、来源、生效/失效时间和不可变版本。编辑生成新版本；未发布修改不会替换已发布版本。停用后停止参与检索，历史草稿保留原依据。

## 录入与首批资料

1. 选择正确项目；新增知识或导入 UTF-8 TXT/Markdown。文件先预览，按一级至三级标题拆分，子条目保留父标题。单次最多 60 条、单条正文 12000 字符。导入只创建草稿，重复内容按项目去重。
2. 核实正文与来源，填写适用产品、条件、生效时间。交易数值在「条件记录」逐项填写主题、值/区间、单位、币种及条件。未确认信息保持「待确认」，指导价格标「参考」，不能当正式报价。
3. 认证资料发布前必须填写适用产品和失效时间；具体证书编号、覆盖范围及真实性由管理员核对。
4. 「已核对，发布此版本」后才能供助手检索。基础销售规则单条不超过 3000 字符；详细政策分条管理。

2026-10-16 本地 Genesis Bags 资料包已整理为 82 条草稿：公司 2、产品 20、交易 6、合规 5、FAQ 48、销售规则 1，未自动发布。模板表达单独归档，阶梯价示意表及生成脚本没有作为政策导入。认证缺少编号/范围/有效期、不同 MOQ 的适用范围、指导价与正式报价的区别，须先确认。具体导入回执和待确认清单保存在本次本地验收输出目录，不含在代码仓库中。

空白整理结构见 [knowledge-entry-template.md](knowledge-entry-template.md)。TXT/Markdown 导入不会自动把自然语言数值转换成已确认条件；管理员需在编辑界面核对并填写结构化记录。第一版不提供 PDF、Word、Excel 的知识导入入口；原有客户附件文字读取保持原功能。

## 何时检索

- 明确委托写开发信、询盘回复、报价说明、样品回复或跟进邮件：进入现有持久任务/分析流程，后端在模型调用前加载项目基础规则与相关知识。
- 邮件线程分析：读取授权线程中的客户需求与历史往来，检索相关产品和政策，逐项记录回答状态。
- MOQ、交期、样品、价格、付款、认证、物流等业务问答：后端强制预检索，模型也可使用只读 search_product_knowledge 工具补充查询。
- 纯翻译/润色：允许跳过知识检索，对新增数字和政策主题做约束；查询客户/统计使用 CRM 工具。

一般知识只取已发布、有效且产品适用的版本。客户邮件只代表需求；模板只提供表达。客户专属报价仅使用本项目、本客户、状态 accepted、未过期且产品和数量匹配的记录。原有客户专属协议如果未形成这样的系统记录，不会被推断为有效报价。

## 生成与审核

模型负责语气和结构；服务端核对数字及业务事实，交易承诺采用有效的条件记录。缺价、缺运费或检索失败时保留有依据的部分，列出待确认事项。冲突来源并列提示，不静默采用其中一个。未经确认的客户要求、模板数字、模型常识不补作我方承诺。

草稿/分析旁的「内部审核信息」显示知识 ID 对应的标题和版本、相关片段及条件、关键承诺与依据、问题回答状态、缺口/过期/冲突。该信息不写入客户邮件。数据库保存原始 sourceId、knowledgeId/quotationId 与版本快照，供追溯。

旧草稿打开时重新核对依据；已发布新版本、停用或失效会提示变化。重新生成明确创建新草稿，保留旧正文和旧快照。手工修改草稿会提示原依据尚未覆盖修改内容。发送仍走原有业务员审核和发送流程，Agent 无自动发送工具；后台自动化只准备草稿。当前账号不能回复其他业务员个人邮箱的来信。

## 验证

| 场景 | 验证内容 |
| --- | --- |
| 跨项目 | 其他项目条目 ID、工具参数及修订读取不能越权 |
| MOQ/交期/样品 | 条件答案引用确切版本 |
| 缺价/运费 | 模型编造数字和免费运费被移除 |
| 时效 | 停用、过期、未来及不同产品知识不进入当前政策 |

| 恶意客户邮件 | 不能引用外项目政策或触发发送 |
| 检索故障 | 独立失败状态与安全部分草稿 |
| 原审核流程 | 持久草稿、不可变依据、更新提示及幂等重新生成 |
| 额外 | 冲突、草稿导入去重、文字转换、内部说明/残留编号、父标题范围 |

## 第一版范围与限制

使用现有 MongoDB 的词项/中英文别名检索，无向量服务。单次候选最多 1000 条，基础规则最多 4 条、其他知识最多 6 条；超限明确标记部分结果。长正文返回相关片段，必要时可补充查询。建议按产品/条件拆小条，使用准确关键词和别名；复杂条件冲突采取保守待确认策略，不能替代完整合同审核或语义证明。

条件记录的值和条件按录入语言呈现，准备英文邮件应录入清晰的英文值及边界。模型自由文字检查是保守规则，不能代替业务员逐句审核；尤其非数字事实的语义、翻译是否改变承诺，仍须人工核对。历史未带生效时间的旧知识需建立新版本审核后使用。

首版无独立长期协议解析、自动认证真伪核验、扫描件 OCR、向量召回评估或自动翻译知识。以上均无伪装成已完成的入口。仅本地开发验收，未部署上线。
